# 范围与关键约束

## 初版目标

一个团队资源 Git 仓库服务多个逻辑项目；成员在不同工作区选择项目和职能，使用统一版本的 AI 资源；项目经验经过贡献、索引、召回形成闭环；会话事件支持本地观测和可选团队汇总。Rust 是实现语言，npm 仅是后续安装入口。

## 暂定选择，实施前在 AIL-001 冻结

- 本机优先验证 macOS，文件与路径模型不写死 macOS；Linux 纳入 CI，Windows 支持待分发卡确定。
- 初版资源适配目标为 Claude Code、Codex，事件采集先验证一个宿主，能力缺口公开呈现。
- 资源存储先支持本地目录和 Git；审核创建先支持 GitHub。其它 Git 源保留手动审核流程。
- 人工创建项目声明或 CLI init 均可作为入口；不假定仅增加隐藏目录就会自动加载。
- 默认锁定 resolved commit，更新是明确动作。后台 Hook 更新不等于当轮上下文已经刷新。

## 不可混淆的概念

| 概念 | 责任 |
|---|---|
| Team | 资源与协作的团队边界，初版由团队仓库承载 |
| Project | 团队定义的逻辑项目，决定相关资源与经验范围 |
| Role | 职能资源选择，与 Project 正交、取并集 |
| Repository anchor | 识别同一 Git 仓库，可用于共享缓存 |
| Workspace root | 当前 checkout/worktree，决定生成资源的落点 |
| Workspace binding | 当前工作区选中的团队源、项目与角色 |
| Resource revision | 可复现的资源发布版本，不等同业务代码 HEAD |

## 数据与行为约束

- 可提交声明与共享内容留 Git；机器路径、凭据、运行态、索引和缓存另存；共享缓存与工作区绑定不能混为一份状态。
- 资源持有者、内容哈希和实际文件共同决定更新/清理；不能靠文件名断定所有权。
- 项目筛选属于资源分发和检索相关性隔离。同一 Git 仓库可被完整读取，不提供保密级访问控制。
- 公共经验与项目经验显式区分；多项目归属不明确时要求选择，不能自动扩大共享范围。
- MCP/Agent 纳入 AILoom 的统一选择模型是产品设计目标，不宣称 TeamAI 已有同等实现。
- 同步成功、宿主发现成功、Agent 实际使用成功是三层不同验收。
- Token 与干预指标保留采集来源及缺失信息；不把启发式纠正计数称为真实错误率。
- 本地实时看板与经 Git 汇总的团队统计有不同刷新时效；共享会话正文需要明确选择。

## 后续范围

成员名册、多源标签、代码知识图谱、图召回、知识维护、npm 二进制分发以及管理后台设计已留卡。组织权限、企业 SSO 与服务端审核平台不纳入首版实现。

## 完成标准

卡片通过其验收并附执行记录；整体初版完成 AIL-023 的端到端链路。当前任务只创建需求卡，不安装依赖、不编写产品代码、不发布仓库或包。
