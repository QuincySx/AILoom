# 资源来源变更与 SSH 别名

状态：核心来源变更流程已实现，2026-10-04；SSH 使用明确映射，自动读取配置与平台 repository ID 核验仍未实现。

## 现状与目标

`CONTEXT.md` 已定义稳定 SourceKey。当前合集创建时仍由 Git 地址的缓存身份派生 source ID（`src/collections.rs`），更新要求新旧地址身份一致；个人 Skill 保存本地目录或 Git URL（`src/skill_source.rs`）。仓库分组与已安装检测只合并基本的 HTTPS/SSH/`.git` 地址形式，没有解析 SSH Host 别名。

目标是让同一已登记来源改变连接时延续 source ID、ResourceId 和项目引用。既有 ID 原样保留，不能根据新 URL 重算。仓库关联、连接方式、资源内容版本分别管理，不以远端相同合并控制台的本机项目。

## 身份与连接

| 信息 | 用途 | 变化时的行为 |
|---|---|---|
| SourceKey / 已登记 source ID | 来源与资源引用的稳定标识 | 修改连接不重建 |
| 上游仓库身份 | 仓库分组、同仓 Skill 识别 | 有平台证据或用户确认后调整绑定 |
| 本机开发目录 | 跟随本地开发内容 | 与上游 Git 关联可以同时存在 |
| Git 连接地址 / SSH Host 别名 | clone、fetch 时选用本机身份 | 保留原连接形式，不改写为展示地址 |
| Skill 仓内路径、跟踪分支、确认版本 | 定位 Skill 与管理版本 | 变更位置或分支要重新预览；不静默升级内容 |

可以获得时，用平台实例与平台 repository ID 辅助识别上游；否则使用经验证的仓库地址别名，并允许手动绑定。GitHub API 返回仓库 ID 与地址，可作为这项识别的证据来源：[Get a repository](https://docs.github.com/en/rest/repos/repos#get-a-repository)。API 不可用不应阻止已有本地资源使用，也不能在离线时假称已核实仓库身份。

同仓的不同 Skill 用仓内路径定位，不能只按名称识别。不同 fork 即使共享提交也保持独立上游。不同分支可以属于同一上游，但不同跟踪选择和版本记录不能因视觉分组合并而丢失。

## 三类变化

### 本地开发后配置 Git

检查已登记开发目录的 Git 根、可用 remotes、Skill 相对路径，给出“关联 Git 仓库”候选。有多个 remotes 时让用户选择，不能默认认为 upstream 与 origin 指向同一份仓库。

关联成功仍跟随本地目录，保留未提交开发内容；远端信息用于分组与多端同步。要改为从远程分支获取更新，再明确选择“跟随远程版本”。资源库已有副本及已部署项目不因 Git 初始化或新增 remote 被替换。

### 修改 Git 链接

在已有来源上使用“变更来源”，先判断新链接与旧绑定的关系：

- 已验证的连接别名：保留身份，调整本机连接。
- 平台改名或迁移且仓库身份一致：提供新地址候选，确认后沿用原登记。
- 指向不同仓库或无法确认：展示“同一仓库换地址”与“替换上游”选择，以及分支、Skill 路径和受影响引用；不能依据同名或共同 commit 自动合并。

GitHub 转移仓库会重定向 Git 地址，但旧位置被新仓库占用后重定向可能消失，因此需要验证当前仓库身份，不能无限期信任旧链接：[GitHub 仓库转移说明](https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository)。

### SSH 主机别名

若本机有效配置确认 `quincy-github` 的 HostName 为 `github.com`，则下面三个地址是同仓候选：

```text
git@quincy-github:QuincySx/skills.git
git@github.com:QuincySx/skills.git
https://github.com/QuincySx/skills.git
```

界面可以统一显示 `github.com · QuincySx/skills`；真正 fetch 仍使用用户选定的 `git@quincy-github:...`，保留对应身份配置。不能根据别名里包含 github 就认定其目标，更不能把任意 SSH 用户名当作可忽略字段。

解析需考虑 Host、HostName、User、Port、Include、Match 及有效规则顺序。普通静态别名可识别；复杂规则无法确定时显示“待确认”并支持手动映射。HostName/端口不同且没有同平台实例的验证证据时，不自动合并。参考：[OpenSSH 配置语义](https://man.openbsd.org/ssh_config)。

`ssh -G` 能输出应用 Host/Match 后的配置，但 Match exec 会执行配置命令，因此不能承诺它是无副作用的纯文件解析：[ssh -G](https://man.openbsd.org/ssh.1)、[Match exec](https://man.openbsd.org/ssh_config)。实现应限制自动识别为可静态确定的规则，或采用用户主动运行并提供的脱敏有效映射；后台不能为了分组自动执行配置命令。

共享配置保存来源身份、可移植仓库地址及资源选择；本机配置保存开发目录和 SSH 连接偏好。每台设备选择自己的身份别名。认证材料不进入资源 Git 仓库。

## 变更来源流程

来源详情 → 变更来源 → 填写或检测候选 → 预览连接、仓库关系、路径、分支与使用位置 → 确认绑定。此步骤只改变来源绑定；内容更新沿用现有“检查更新 → 预览 → 更新资源库 → 项目应用”流程。

新连接验证失败、Skill 路径不存在或用户取消时，保留旧绑定与旧资源。确认前核对登记 revision；变更保存后使旧安装和更新候选失效，提示重新扫描/检查。变更本身不会替换本地内容、重置已确认内容版本或改项目部署。

Git 缓存身份与 SourceLock 当前也受 URL 约束，迁移必须重新建立与新连接一致的缓存和锁，或保留可验证的旧快照连接记录；不能只编辑 URL，留下与其不一致的锁。旧版本与实体保留，来源登记采用可恢复的原子保存。已经存在的重复来源需另行预览引用迁移，不能直接删除其中一份来“去重”。

## 目标验收矩阵

下表包含已覆盖场景与后续目标；实际覆盖以本轮验收报告为准，不能把整个目标矩阵视为已通过：

| 场景 | 期望 |
|---|---|
| 无 Git 的开发目录新增 Git 与单个 remote | 提供关联候选，ID、引用和本地正文保持 |
| origin 与 upstream 不同，或 remote 被修改 | 要求明确选择绑定，不默认认定同仓 |
| 同仓 SSH 别名、HTTPS 与普通 SSH | 分组与已安装检测一致，实际连接保留别名 |
| 名字含 github 的别名实际指向另一主机 | 不误合并 |
| 不同端口、SSH 用户或平台实例 | 缺少验证映射时不误合并 |
| 静态 Include、Host 通配符、复杂 Match | 按规则给出确定结果或待确认，不偷偷执行命令 |
| 同仓改名/转移；旧 URL 后来属于新仓库 | 已验证迁移可关联，新仓库不能冒用旧绑定 |
| 不同 fork 含相同 commit | 不以共同提交认定同一仓库 |
| Skill 移动、改分支或改仓库 | 明确预览路径和版本，旧内容可用 |
| 连接失败、预览过期、写入失败或取消 | 原绑定、内容、引用保持；可重新预览 |
| 变更后执行旧更新/安装预览 | 明确拒绝旧候选，要求重新检查 |
| 两台机器使用不同 SSH 别名 | 来源身份和资源选择共享，连接偏好各自保留 |

## 本轮已实现

- 资源库个人 Skill 行提供“关联 Git / 来源”，合集来源详情提供“变更来源”。检测本地 Git 根、仓内路径、分支与所有可用 remotes；多 remote 须选择。
- 预览后保存只更新来源元数据或登记中的 `connection`，保留原 ID、正文、确认版本、导入摘要与项目引用。合集继续从原 URL + SourceLock 读取旧快照；检查更新使用新连接，显式更新后切换内容锁。
- 本地关联默认继续跟随开发目录；可明确切换为远程版本。未知仓库关系须确认同仓换地址或替换上游，不能凭共同 commit 自动识别。
- SSH 接受用户填写的 Host/HostName/User/Port 明确映射，实际 fetch 保留原连接地址；后端提供同一仓库分组身份与已安装检测。
- 来源保存使用库更新锁、合集登记锁和原子写；核对源元数据、正文摘要、登记 revision、绑定 stamp 与缓存锁。旧绑定/安装/更新预览失效。Git 缓存 fetch 使用当前连接，并确认远端默认分支。
- 知识库 checkpoint 只导出可移植地址；删除本机目录与 SSH 连接偏好。坏旧格式来源字段移除，恢复时拒绝夹带本机连接的来源声明。沿用现有知识库资源打包/恢复和引用映射机制，没有重新设计跨设备来源合并。

## 当前边界

自动读取真实 SSH 配置、Include/Match 解析、GitHub 平台 repository ID 与转移重定向核验、重复来源引用迁移尚未实现。SSH 映射和地址改变的关系确认由用户明确提供。没有用名字、共享 commit 或旧链接永久重定向推断同仓。

本轮真实 Git/CLI/HTTP 与浏览器验收使用隔离的本地仓库。没有读取本机 SSH 认证目录，没有改变用户实际来源绑定。写入失败与 SIGKILL 恢复未做故障注入；并发防护和原子保存已审查，但不冒充崩溃注入通过。
