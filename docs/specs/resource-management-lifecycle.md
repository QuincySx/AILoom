# 资源管理生命周期

## 首次设置与日常入口

首次进入没有完成标记时显示向导，每次只显示一步：选择项目 → 确认工作树 → 选择宿主与资源（可内联导入）→ 预览 → 应用 → 完成设置。草稿保存在本机数据区；完成设置不等于宿主真实调用验收通过。

资源库是管理入口，不只是导入表单。每个合集显示来源地址、资源数量、已确认版本、检查时间、更新状态、启用引用、实体路径和移除操作。导入表单按需打开，先选择 GitHub、GitLab/自建 GitLab、其他 Git、本地 Skill 文件夹或 skills.sh 单项入口。

## 三个动作，不混淆

| 操作 | 修改什么 | 不修改什么 |
|---|---|---|
| 检查全部更新 | 获取候选快照、保存检查状态/时间/错误 | 不推进资源库版本、不改项目 |
| 更新全部可用版本 | 确认预览后，一次保存所选合集锁定版本 | 不重取漂移分支、不自动改项目 |
| 应用到项目 | 预览并确认当前项目/作用域的文件与链接 | 不升级未选择的其他工作树 |

检查结果持久化在 `collections/checks`，可用更新显示在资源库与更新中心。检查失败单独展示，不当作已是最新。没有定时后台轮询；用户点击检查后才访问上游。批量更新预览过期则明确拒绝、要求重新检查；不是把部分来源静默更新。

个人库中有 Git 来源的 Skill 副本也参与检查，候选保存在 `<data>/library-updates/<name>.json`，包含固定 commit、本地摘要和检查凭证。更新复用该快照；再次检查或本地编辑使旧候选失效。本地来源和没有来源记录的旧副本不提供上游更新。

个人 Skill 逐项更新，失败会列出具体项；与合集混合更新时不保证整批回滚，合集失败后仍继续独立的个人 Skill 更新。每项先暂存完整候选，替换或整库校验失败则恢复旧目录，旧版保存于 `library/.updates-backup`。检查开始时作废旧候选，检查与应用失败状态保存在后台，页面刷新后仍可诊断并重新检查。

目录替换前原子保存 `library/.updates-journal.json`，完成整库校验后记录已提交。下一次列表、初始化、导入、检查、应用或删除会先处理遗留事务；也可运行 `ailoom library --action recover --json` 查看恢复结果。未提交事务恢复旧目录，已提交事务保留新版，恢复后旧检查凭证作废。恢复本身再次中断也可重试；若待恢复目录或备份已被修改，保留现场并报告冲突，不覆盖后续修改。恢复移开的候选保留在 `.updates-staging`；不自动重新抓取或应用更新。

上游删除仍被引用的资源时阻止更新，用户需先替换/取消引用。项目部署仍走既有所有权、Git 跟踪文件和本地后改冲突保护。

## 文件怎么保存

- 作者：在自己的 Git 仓库编辑、提交、推送；AILoom 不替用户推送。
- 来源：`<data>/collections/registry.json` 保存 URL、ref、确认的 commit；快照存在独立缓存。
- Skill 实体：`<store>/github.com/owner/repo/revisions/<commit>/<skill>`；本地来源为 `local/<名称+身份摘要>/revisions/<版本>`，无锁定版本的可变个人源为 `working`。
- 项目使用者：仓外 profile 保存资源引用和作用域；每个工作树的托管清单保存部署记录。Skill 用链接共享实体，MCP 将配置合并到宿主对应文件，不把 MCP 当作 Skill 文件夹。
- 来源更新保留历史实体，项目确认应用时才切换链接。旧 Base64 实体不搬走、不删除；下次同步逐工作树切到可读路径，未同步的工作树仍可使用旧链接。
- 根目录优先级沿用 `$XDG_DATA_HOME/ailoom/store` > `AILOOM_STORE_ROOT` > `$HOME/.local/share/ailoom/store`。本次没有改变根目录优先级。

## 删除与恢复边界

1. 项目不用某资源：在仓库与作用域停用，再预览并应用，清理该项目的托管产物。
2. 移除合集来源：先预览启用引用；存在引用时拒绝。确认后只移除登记，来源记录存入 `collections/archive`，缓存和实体保留，可重新添加相同 URL 恢复来源。
3. 删除个人副本：启用引用会阻止删除；成功后移入 `<data>/library-archive/<id>/`，不永久删除。当前恢复需要手动从归档重新导入。
4. 清理磁盘缓存：本次未实现安全 GC；不能承诺移除来源立即释放空间。保留旧实体避免断链，后续清理必须核对所有工作树的实际链接和离线项目。

## 验收与限制

验证导入、检查、更新、引用保护和移除使用隔离本地 Git fixtures；GitHub/GitLab 的认证与网络状况未作为本地测试通过的保证。混合 MCP 资源仍要求 `ailoom.toml`，不会解析任意 README 中的 MCP 配置。真实宿主调用另行验证。
