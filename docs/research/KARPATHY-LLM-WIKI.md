核实日期：2026-10-23。范围：为既有的单 Markdown 整理报告改进提示词，不扩展存储或执行权限。

- 三层结构：原始资料只读；模型维护相互关联的 Markdown wiki；schema 规定结构、惯例和工作流。[Architecture](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f/ac46de1ad27f92b28ac95459c782c07f6b8c964a#architecture)

## AILoom 提示词适配建议

以下是本项目设计建议，不是原文规定的 schema。按现有单报告接口，把 wiki 的职责映射为文档内的可导航知识单元：

| 报告部分 | 提示词应要求的行为 |
|---|---|
| 知识导航 | 按主题提供概念、实体与决策的短说明和文档内链接；采用明确、稳定且不重复的标题。 |
| 来源目录 | 为实际读取的原始文件分配来源编号，保留真实路径及可核对的标题、章节或行号；未读取或不可访问的来源单列。 |
| 核心知识 | 合并重复记录、统一术语和别名；按问题或主题组织，不按原文件逐篇堆叠。记录定义、关系、适用范围及证据。 |
| 综合与决策 | 联系多个来源形成可复用结论；分清来源明确记载的事实、决策、模型推断和建议。决策应保留背景、理由、约束及已知替代方案。 |
| 矛盾与缺口 | 保留冲突双方及各自来源；只有存在明确时间、范围或替代证据时才能判定旧说法失效。不能解决的冲突和信息不足应显式保留。 |
| 演进摘要 | 若可读到旧报告，比较新增、修订、失效及待核实内容。旧报告只作组织与比较线索，每项保留结论仍需回到原始证据；无法核实时说明原因。 |

在生成正文前执行 ingest 式整理，在输出前执行 lint 式自检：重要结论是否有来源、推断是否标注、术语是否一致、内部链接是否存在、矛盾是否被隐藏、旧报告是否被循环当作证据。不给没有读取的材料补造路径、日期或结论。

保留既有只读边界：模型只返回一份完整 Markdown，由应用保存。文档内导航和演进摘要分别借鉴 index 与 log 的职责；这不等于创建了多文件 wiki、查询服务或追加式历史日志。当前调用也不应自行联网补资料，资料缺口留给后续行动。

单文档会在整理后覆盖原位置，因此旧报告的路径和行号不能作为历史证据链接。比较旧结论时使用旧主题 ID 或必要短摘录，事实依据仍回到原始资料；独立的完整历史由任务记录保留。

## 限制

原文是可组合的模式说明，没有提供通用输出 schema 或质量基准。单报告适配能改善结构与证据透明度，是否提高后续 AI 使用效果仍需用真实碎片资料评估。建议人工检查一组包含重复、冲突、过时记录和无法读取来源的输入，确认整理后能准确回答跨来源问题，并追溯到原始资料。

## 本地样例验证

2026-10-23 使用本机真实 Codex 在隔离项目中完成三轮整理：先处理三份含重复经验和矛盾便签的资料，再加入第四份原始状态记录并纠正旧报告的无来源断言，最后复查覆盖式保存下的引用规则。

- 既有主题 ID 在更新中保留，导航与主题链接均能定位。
- 完整来源目录覆盖全部四份输入，原始文件逐字节保留，整理结果可由知识检索找到。
- 旧报告中“自动回滚已实现且测试通过”的断言被撤回确定性状态；新结论回到原始资料，并区分来源记录、本次静态核对和未执行的测试。
- 矛盾便签继续保留适用版本与效力的待核实项，没有按多数意见裁决。
- 复查发现旧报告行号链接会在覆盖后失效，因此模板补充禁止报告文件自引的规则；最终一轮核对通过原文链接、内部锚点和无报告自引检查。

相关知识模块的七项测试、Clippy、格式和文档检查通过。以上是有限样例验证，不是通用知识质量基准。
