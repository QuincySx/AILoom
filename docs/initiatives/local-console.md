# 本地控制台与个人项目配置

状态：规划已拆卡并实现（2026-09-16：039-050 Done，051 Blocked 等待人工试用者验收）。依据：[需求与回复审查](../reviews/2026-09-15-onboarding-requirements-review.md)、[ADR-0002（proposed）](../adr/0002-repository-scope-personal-layer.md)。本计划不是 v1 已冻结能力；改变语义必须由 AIL-039/040 在 CONTRACTS 中新增版本/迁移条目，不直接改旧含义。

## 产品目标

让个人在公司仓库里管理自己的 skills、MCP、指令和研发文档，优先用本地网页完成设置。默认不要求团队源、不要求网络、不更改公司已有跟踪文件，也不隐藏用户本来就有的 Git 改动。已有 CLI 业务逻辑继续复用。

必须区分三个动作：保存个人配置、应用到选定工作树/宿主、导出或贡献到团队。前两者不能隐式触发第三者。主界面默认展示本地配置与真实生效状态；高级信息才展示源键、工作区 ID、底层文件路径。

## 第一次使用的流程

1. **启动与恢复**：一个本地启动入口打开浏览器；未安装可展示安装入口，CLI 仍是回退方式。已有设置时进入最近仓库，不重走向导；端口占用可选择可用端口，服务断开有重连反馈。
2. **选择目录**：提供“当前目录”和“选择已有文件夹”。普通网页无法无授权读取任意本机目录；通过本地服务的受限目录选择器或明确路径输入，不能假装上传目录即可获得本机真实路径。不扫描全盘；用户选择扫描根后再发现。
3. **确认归属**：展示仓库名、当前工作树、分支和其他工作树。Git 项目自动归组，非 Git 文件夹显示路径模式。多 origin/upstream、同远端独立克隆等仅在歧义时询问，不把技术术语作为所有新手必答题。
4. **选能力**：先选已安装宿主，再选少量 skills/MCP 或“需求→规格→票据→实现”流程包。支持从指定本地 skill 目录预览导入；看内容不会执行脚本。团队源、角色和 namespace 放在高级选项。
5. **预览应用**：列出将影响哪个工作树/子项目、宿主、文件和进程；默认只应用当前工作树。清楚显示“公司已跟踪文件不修改”、新增忽略入口、需连接/安装的项及冲突。无变化则不触发空任务。
6. **验证与继续**：分别显示已保存、已部署、宿主已发现、调用通过、需新会话、不支持/未验证。成功后给出一个可执行的使用动作，如“在选定宿主使用该 skill”，而非只显示绿色“同步成功”。

向导每步可返回、不丢草稿；可跳过 MCP 或未安装宿主继续配置 skill；服务/浏览器重启可恢复未完成状态但不能自动重放执行动作。第一条完整路径不要求编辑 TOML、创建远端、复制凭据或修改公司指令文件。

## Git 与配置规则

- Repository、Worktree、Scope 与业务 Project 分离。先询问 Git 身份，再查所选 Git 边界内登记的配置作用域；子目录声明不是退出 Git 身份的理由。子模块与嵌套独立仓库默认不继承外层个人仓库配置。
- Git common-dir 识别关联工作树，`worktree list --porcelain -z` 枚举；工作树不一定在共同父文件夹下。bare 根是仓库容器，不是部署目标；detached、locked、prunable、失联状态可见且不能误写。
- 本地注册 RepositoryId 不以 origin URL 为不可变主键；common-dir、规范化远端和位置作为发现证据。多个独立 clone 同远端只给关联建议；多远端/SSH alias/重命名不默默合并或吞掉原配置。无远端 Git 不等于非 Git。
- 稳定 worktree 注册关联当前位置，移动/删除需要重关联/失联标记。旧 path-based workspace_id、事件、锁、托管清单明确迁移；不能为追求仓库归组而合并所有事件/journal。新发现工作树继承配置视图，但不自动向未选工作树写入。
- 从低到高：团队声明 → 个人仓库默认 → 仓库子项目模板（相对路径，由浅到深）→ 当前工作树覆盖 → 当前工作树子项目覆盖（由浅到深）。展示每项值的来源；同层冲突先解决，不能靠遍历顺序赢。
- 资源开关用“继承/启用/禁用”；禁用是显式值，空列表和未设置必须区分。沿用 v1 时不擅改原角色∪项目选择规则；新增个人选择层覆盖的是期望部署，不提升源读取权限、不重写团队声明。
- 多层会生成同一宿主入口时由统一计划器计算有效配置，不允许父子两个 sync 抢同一路径。某宿主无法屏蔽祖先/全局技能时，标为“AILoom 不部署/宿主仍可见”或提供已验证启动方式；不得假装子项目禁用真的隔离了宿主全部能力。
- 仓库可共享所选配置，worktree 仍保留独立分支/工作内容。示例：web/docs 子项目模板对各工作树同相对路径生效；某工作树没有该目录时显示未匹配，不自动创建业务目录。

## 公司文件保护与本地指令

个人配置、源材料与 WorkflowArtifact 默认保存在仓外机器数据区，项目根 `.ailoom/project.toml` 不是个人模式必填项。团队模式才编辑可提交声明，且保存前预览。

公司已跟踪的 AGENTS.md/CLAUDE.md、宿主配置和 index 不被个人 apply/sync/uninstall 改写；既有 unstaged/staged 修改保持原样。新入口若已被 Git 跟踪或用户已有内容，必须报告冲突，不借助 skip-worktree、assume-unchanged、git rm --cached 隐藏修改。

需要在工作树放本地入口时，仅管理本次生成的独立文件；本地 exclude 通过 Git 路径解析访问，保留用户条目，考虑 common-dir 多工作树共用与卸载引用计数。ignore 不是强制 add 的防泄漏保证：产品只承诺默认工作流下不改公司跟踪文件、不主动暂存/提交个人内容。要求工作树零新增文件时，只允许已验证的外部/启动时注入路径，不支持就明确显示能力限制。

指令层提供“补充偏好”和“基于公司基线的个人替代视图”，原公司文件只读。替代视图记录基线摘要和个人 patch，宿主层若替代整个文件必须包含未调整的公司内容；上游变更或切换分支后检测过期并重新合成/提示冲突，不能永久冻结一份旧规范。语义是生成供特定宿主加载的视图，不保证抹除其他来源或更高优先级指令。

每个适配器记录支持版本、加载顺序、native/生成入口/启动注入方式、是否需要新会话、有效作用域；不用同一个 AGENTS.override.md 规则套所有宿主。Codex/Claude 优先做本地真实加载探针；其他宿主现有部分支持保留准确矩阵，不默默修改用户全局配置或信任设置。

## Skill、MCP、源和文档

个人资源库复用 source manifest，但首次自动生成。从用户指定目录导入 skill 时预览 SKILL.md 与附属 assets/scripts/references、名称/版本冲突；默认复制到个人库，原目录不改，禁止默认执行附带命令。更新提示并展示差异，不把远端刷新等同自动信任/执行。

编辑源配置与资源正文时保留未知字段/注释，使用文件版本指纹防止覆盖外部编辑。远程团队源默认作为订阅只读；修改进入个人副本或明确贡献草稿，不隐式 commit/push。支持启停订阅、固定版本、离线状态、无效资源可定位；删除源先展示受影响作用域与托管项。

每个资源按完整 ResourceId 和宿主/作用域配置三态选择；MCP 服务可单独开关、检查缺少的依赖与引用配置，连接探测仅由用户明确动作触发。秘密只使用引用与缺失状态，不通过 API/日志/导出暴露；设置成功不等于连接成功。

流程包组合四类 skill 与文档模板。一次流程有稳定 ID、阶段、输入版本、对应 spec/ticket/implementation/review 产物；重命名不丢关联，规格变更使下游显示需复核，不自动删除/覆盖或宣称票据已实现。个人文档默认仓外；用户明确导出单个产物或包时预览路径和 diff。现有 doc 的同步副本与可编辑流程产物分开，不让 sync 覆盖正在写的 spec。MVP 不自动调模型、不自动派 agent 或发布票据。

## 本地 Web 写入协议

复用内部业务服务/结构化参数调用，不提供任意 shell 或任意 CLI 执行接口。请求使用注册资源 ID/ScopeId，后端重新校验路径边界和宿主能力；本地文件内容按不可信文本处理并转义。

仅绑定 loopback；启动建立短期本地会话，写入验证认证及 Origin/Host，拒绝跨站请求与 DNS rebinding 形式的未知 Host，不开放通配 CORS。目录选择限用户授权根；配置编辑、文档预览、日志和浏览器响应不泄露机器秘密。只读看板不能直接复用为无鉴权可写服务器。

配置保存用 revision/ETag，过期保存返回冲突并保留用户草稿。plan 固定配置、源版本、目标状态和范围；apply 检查 plan 未过期，不能应用在错误 worktree。任务有 ID、进度、错误、有限日志和幂等键；取消只在安全边界停止，部分应用可恢复，不谎称全部回滚。

MCP 连接、包安装、Hook 启用属于可能执行进程的动作，不能由页面预览/扫描自动触发。当前任务没有授权创建真实远端发布，Web 的“保存/应用”也不得顺带发布。
