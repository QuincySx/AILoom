# AILoom 知识生命周期原型（提案，非生产功能）

打开 `index.html` 即可，CSS/JS 全部内嵌，无网络依赖、无持久化、无真实文件操作。`theme.css` / `theme.js` 是按 artifact-design 复制的原始视觉资源；交付 HTML 不依赖这两个文件。

回答的问题：知识是否能在使用 AI 时逐渐积累，同时保证可编辑、可纠错、可归档和可迁移？

## 阅读顺序

1. 先看结论：代码的现状和缺口。
2. 完整流程：用户、AI、Hooks、CLI、网页各自做什么。
3. 场景演练：8 个可操作场景，可以切换自动候选 / 自动正式 / 每次确认。
4. 软件分工：配置、知识、工作产物的区别；CLI、网页和插件的关系。
5. 你的选择：记录尚未确定的需求并导出文本。未预选答案，导出不保存产品配置。

## 本轮代码核对

- [Hook 调度](../../../../src/commands/hook_reg.rs)：事件采集、配置 auto_sync、Stop 摩擦提醒，不调用模型提炼知识。
- [事件采集](../../../../src/events/hooks.rs)：内置采集分支为 Claude；不等于所有宿主都自动维护知识。
- [经验 Skill](../../../../src/adapters/res/share-learning-skill.md)：提炼草稿、用户审阅、contribute。
- [召回 Agent](../../../../src/adapters/res/recall-agent.md)：按需调用 recall 的软约束。
- [知识保存](../../../../src/knowledge/location.rs)：同名不同内容拒绝；保存位置与 Git 同步独立。
- [贡献入口](../../../../src/commands/contribute.rs)：已初始化知识库分支直接调用 save，未执行旧贡献流程的 persist_identity / 内容更新步骤。因此旧分支的稳定身份更新能力不能被当成新分支也已具备。
- [维护](../../../../src/knowledge/feedback.rs)：显式反馈、归档 / 恢复及维护建议。低频不直接等于应删除。
- [上一轮验收](../../../reviews/2026-09-29-knowledge-acceptance.md)：迁移、恢复、同库跨项目可见等实际证据。

## 尚未确定，不能据此改生产数据

自动记录默认策略；候选是否参与检索；矛盾知识更新权限；同库多项目隔离；六个 Skill 的实际产物适配位置；自动提炼由哪个宿主或执行入口触发，是否需要常驻任务。

原型默认是自动候选、矛盾需确认、同项目共享 / 不同项目隔离。它们是可试用假设，不是用户已批准的设计。人工编写和 AI 编写最终应使用同一套更新契约，不能绕过归属、版本或冲突检查。

使用 ORCA DOM click 执行交互；此环境的 ref click 返回成功但未触发页面操作，不能据此宣称原生点击链路已验证。浏览器 console 未返回错误；额外检查内嵌 JavaScript 语法通过。
