AILoom / 知识使用与维护需求对齐原型 · 2026.09.29

知识应在工作中积累，维护时找得到、改得动。

这份原型验证：你是否可以照常使用 AI，AILoom 负责把有价值的内容留在正确的项目里；你偶尔打开网页，就能修正错误、整理旧内容、带到另一台电脑。

目前还没有完整实现这个闭环。
Hooks 已有事件采集和提醒；自动提炼、持续更新知识、网页编辑仍有缺口。下面的可点击页面是提案，不是已上线功能。

现在的代码实际做了什么

  • 使用 AI 时：采集事件，不等于记录知识现有内置 Hook 针对 Claude，记录标准事件；出错或反复纠正较多时提醒沉淀经验。没有在这里调用模型总结会话。 [S1]
  • 编写经验：AI 或你主动执行内置 Skill 先生成草稿、请用户确认，再执行 contribute。检索 Agent 也需要被调用；不是每次对话都保证自动召回。 [S2]
  • 存储、迁移、恢复已有基础保存和检索可用；同项目 Worktree 共用绑定。网页能管理保存位置，但不能管理知识正文。 [S3]
  • 更新旧知识：流程没有统一新知识库保存入口遇到同名不同内容会拒绝；contribute 在此分支也直接走保存，尚未形成稳定的修改闭环。 [S4]

建议的使用感受

日常工作不需要反复进入管理页，也不需要手工搬文件。

  1. 初始化时选保存目录和自动记录方式。
  2. AI 提炼有价值的结论，附来源和适用范围。
  3. 下一次工作按需检索，区分候选与已确认。
  4. 遇到重复或矛盾，合并建议留给你处理。
  5. 修改、归档、恢复，都留下可追溯记录。

自动保存到候选区是本稿假设；不是已经替你决定的默认值。

“box”暂按 Hooks 理解；如果你指另一个组件，可在“你的选择”里写下。

从一次工作，到下一次少踩一个坑

提案中的职责划分：Hooks 触发，AI 提炼，CLI 落盘，网页管理。同一套知识不因入口不同而分成两份。

01 · 用户 / AI完成一次任务

修复问题、澄清约定，或完成规格与设计。

02 · AI + 触发入口判断是否值得保留

有可复用结论才提炼；没有就结束。不把完整聊天当成知识。

03 · AILoom CLI写入当前项目

核对归属、查重、保存来源；按你的记录策略进入候选或正式区。

04 · 下次使用按任务召回

返回相关内容、出处及状态。候选内容不能被说成已确认约定。

新结论，与已有内容无冲突

自动候选 / 自动正式 / 每次确认，由你选策略。自动正式仍需保留修订记录。

重复、相互矛盾或适用范围变化

不静默覆盖；提出合并或替换建议，确认后更新同一条知识。

05 · 用户 / AI反馈或纠错

这条有用、已过时、结论不对，或直接编辑 Markdown。

06 · AILoom维护同一条知识

更新保留旧版本；归档停止召回；恢复重新参与召回。

07 · 独立动作同步与备份

本地保存完成不等于 Git 已提交或远端已同步；冲突单独处理。

08 · 另一台电脑恢复关联

读取随项目走的声明，选择本机位置，再拉取或关联知识库。

当前的实际分支

Claude Hook → 事件文件 → 达到条件时提示。
用户 / AI 调用 Skill → 草稿审阅 → contribute → 已初始化的知识库。
用户 / AI 调用 recall → 返回检索结果。

Hook 中的 auto_sync 是刷新与应用能力配置，不代表自动提炼知识，也不代表知识库已经推送到远端。[S1–S4]

需要补上的连接

AI 提炼触发机制、候选状态、冲突与重复处理、原位更新和版本恢复、网页正文管理、Skill 产物归档规则。

不能只做一个“自动保存”开关，就声称这些步骤已经存在。

    当前状态

    AILoom 管理什么，哪些事情交给 AI？

    • AI 工具：理解和编写Claude、Codex 等负责提炼结论、生成文档、提出更新。是否能自动触发，需要逐个宿主适配，不能假设都一样。
    • AILoom CLI：一致的文件操作解析项目、保存与检索、验证更新、维护记录和恢复位置。独立使用，不要求网页常驻。
    • AILoom 网页：管理入口看内容、编辑、处理冲突、看保存与同步状态。网页服务运行时可访问。
    • ORCA 插件：另一种入口调用同一 CLI，利用当前项目上下文。不会取代独立 CLI / 网页；插件方案仍需另行验收。

    不要混在一起的三类内容

    能力配置Skill、Rules、Agents 和项目说明：告诉 AI 怎么做。
    积累的知识经验、约定、决策和纠错：告诉 AI 已经知道什么。
    工作产物规格、任务、ADR、原型：工作本身生成的文件。可以进入检索，但不要复制成另一份经验正文。

    知识库可随业务仓库保存，也可放独立 Git 或本地目录。位置和是否 Git 同步，是不同选择。

    整个软件的另外两条日常路径

    给项目装能力

    导入本地 / Git 来源或迁移 CC Switch → 能力库看到资源与更新 → 在项目里选 Skill、Rules、Agents → 预览文件变更 → 应用到 AI 工具。

    本地原有内容与 AILoom 托管内容分开展示；子环境默认继承，必要时独立选择。能力库的更新不等于知识内容同步。

    管理现有规则与项目说明

    读取已有文件 → 查看来源和生效范围 → 编辑 → 选择写回方式 → 预览并应用。

    “仅本机生效”必须按文件是否已被 Git 跟踪区分。Git ignore 不能隐藏已跟踪文件的修改，不能让一个勾选项制造这种保证；这条路径需单独验证。

    用具体选择，对齐你的预期

    可以先去“场景演练”点一遍，再回来选。不会修改 AILoom 设置；导出文本发回来即可。

    1. 使用 AI 时怎么积累？
    2. 新结论与旧知识矛盾时？
    3. 多个项目使用同一知识仓库？
    4. Skill 产物优先放哪里？

    从这几个问题判断是否好用

    • 日常写代码时要不要不断确认？
    • 错的知识会不会反复被 AI 引用？
    • 同一条知识会不会越改越多份？
    • 不打开网页时，还能否正常积累？
    • 换电脑后，是否需要重做配置？
    • 保存失败或 Git 冲突，会不会丢掉刚写的内容？
