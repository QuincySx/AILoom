用户视角的完整旅程。1~8 步是急用版主链路；任何一步取消都零写入。

①项目登记（Git / 非 Git 同一入口）

普通文件夹就是一等公民：不 init、不推远端、不搬文件。

UI 项目 → 新建项目 DialogAPI /api/repo/discover · /api/projects/metadata · /api/fs/*落盘 data/repos/<id>/ + registry
新建项目→ 选路径（手填/目录浏览）→ discover：识别 Git / 普通目录→ 命名+分类→ 确认 or 取消？
确认 → 建 repo-id、写登记 → 自动打开项目页，徽标显示「文件夹项目 / Git 项目」。
取消 → 零写入：repos 目录、profile 都不变（门禁断言项）。
日后目录失联？→ 项目页顶部「目录失联」面板
恢复路 A：把目录移回原路径 → 点「重新检查」→ 原项目恢复（配置保留）。恢复路 B：在新路径重新登记 = 新身份，不合并。

②宿主启用 / 停用（含继承）

决定 Claude Code / Codex CLI 是否接管这个项目。

UI 项目页 · 宿主页签API /api/profile/select · /api/hosts/detect · /api/effective落盘 profile.toml 的 hosts 键
宿主行下拉选→ 选了什么？
├─ 启用/停用 → 写本层键 →「保存」→ effective 立即可查（UI 与 CLI 同读一份）
└─ 恢复继承 → 删除本层键 → 有效值回到上层
「检测版本」按钮→ hosts/detect→ 显示本机版本｜ 未检测≠未安装（文案明示）
非 Git 项目只有「项目默认」一层，工作树层仅 Git 项目可用；无效的范围控件直接禁用而非报错。

③扫描项目里已有的 Skill（只读）

不登记也能看见：项目目录里已经存在的 Skill 被发现并分类，不动任何文件。

UI 项目页 · Skill 页签下方「项目目录里的 Skill」API /api/project/scan-skills（有界扫描：宿主目录深≤2、自定根深≤3）
填 Skill 根（如 skills）→ 点扫描→ walkdir：跳过 .git/node_modules/隐藏目录，不跟随链接内容→ 每项分类
├─ 无 frontmatter 引用 → 项目自有未托管（无虚假的版本/更新按钮）
├─ 符号链接指向 store → AILoom 托管（去重：已在引用列表的不重复列）
├─ 符号链接指向外部 → 外部链接（只报分类+目标路径，不读内容）
└─ SKILL.md 损坏 → 独立报错，不锁定整张列表
守卫：扫描前后源文件哈希逐字节不变；结果只读展示；接管=导入副本（原目录不动）；删除走独立双确认（见 ⑩）。

④资源入库（全局资源中心）

四种来源汇入同一个资源库；扫描≠入库，入库才可被项目引用。

UI 资源中心 /library · 各处「＋导入」Dialog（共用组件）API /api/library/import(-entry/-git) · /api/collections/preview+apply · /api/migrations/cc-switch/*落盘 data/library/ 个人副本
＋导入→ 来源类型？
├─ 本地文件夹 → 填存储名（须 ASCII）+浏览 → 预览 → 确认 → 复制为个人副本（原名目录不动）
├─ 合集仓库 → preview → apply（E3003 逐项处置：仓内链接放行、外逃/悬空定位跳过）
├─ Git 来源 → 走既有服务克隆入库
└─ CC Switch → scan → read → preview → apply（迁移既有来源）
入库成功 → 刷新目录、选中新条目｜ 「检查更新」→ library/check-update / update
守卫：取消导入零写入；导入失败不撤销已入库的其他资源；全局导入成功≠任何项目被暗启用；删除库内资源走 CLI 化的 library/delete（移入 library-archive 可恢复）。

⑤项目内添加引用（含 ＋导入 不离页）

UI 项目页 · Skill 页签 →「添加Skill」Dialog（resourcePicker）API /api/resources · /api/profile/select落盘 profile.toml 的 resources 键
点「添加Skill」→ 库里有没有货？
├─ 有 → 搜索（真实名称/说明）+ 来源分组 + 已添加项禁选标注 → 勾选 →「添加所选」
└─ 空 → 空态如实显示（不 undefined），Dialog 内直接「＋导入」→ 导入成功自动选中新条目 → 回到同一 Dialog 继续（全程 hash 停在项目页）
逐项保存 profile→ 某项失败？
全部成功 →「已保存 N 条引用」，引用列表立即出现。
部分失败 → 如实报「已保存 X 项；Y 项失败」+列失败项；成功项不回滚；仅失败项保留勾选，重试只补失败项。保存期间搜索/勾选/重复提交/切项目全部锁住。

⑥移除引用（两种语义，说清楚再动手）

UI 引用行 →「从本项目移除…」DialogAPI /api/profile/select（inherit=删键）
点移除→ predictAfterClear：预测清除本层后的有效值→ Dialog 两个选项
├─ 清除本层设置 → 删键回到继承；确认文案按预测如实说
└─ 在本范围停用 → 写显式 disable；应用后清理磁盘托管文件
关键区分：上层（项目默认）已 enable、工作树也 enable 时选「清除本层」→ 文案明示「上层仍启用，文件不会被清理」，plan 也确实无清理动作——不承诺做不到的事。停用项不会被选择器误判为「已添加」而禁选，可重新勾回启用。

⑦预览与应用（显式两步，结果必现）

UI 项目页 · 预览与应用页签（planPreview JobPanel）· 顶部「待生效」横幅API /api/jobs/plan → /api/jobs/apply → /api/jobs/undo · /api/jobs/<id> 轮询落盘 项目目录 .claude/skills/… · 持久化任务记录
生成预览→ plan：算出要写/删哪些文件→ 有差异？
├─ 无变化 → 如实说「无改动」（应用按钮不给点）
└─ 有差异 → 差异清单 →「应用」
apply 写盘→ JobPanel 结果面板
成功必显示：「应用完成：写入 N 项」+ 每宿主写入路径表 + 撤销入口 + 「需新会话生效」提示。不再停留进度文字；过期结果（切了目标/范围）直接丢弃不回写旧 DOM。
失败/部分失败也在此面板如实列出；「操作记录」页可 undo。改了配置忘了应用时，项目页顶部常驻「待生效」横幅一键跳预览。

⑧磁盘部署状态（四态，多宿主逐个说）

UI 引用行第三段徽章API /api/deploy-status（期望 artifacts × manifest 比对）
deploy-status→ 比对结果？
├─ current 已部署（与资源库一致）｜ stale 待更新（库已变）｜ not-deployed 未部署
└─ 查询失败 → 未知 + 重试按钮（绝不把失败说成「未部署」）
两宿主一旧一新 → 显示「各宿主不一致」并逐宿主列出，不乐观聚合称「已部署一致」。

⑨Markdown 个人指令

UI 项目页 · Markdown 指令页签；独立 /instructions 页同样上报脏状态API /api/profile/instructions · /api/draft落盘 项目默认层指令 → apply 时写 .claude/rules/ailoom-personal.md 等
编辑文本→ 未保存就切页签/范围/路由？
├─ 是 → 放弃确认 Dialog；取消则草稿原样保留（不丢稿）
└─ 否/确认 → 保存 → 生成待生效 → 走 ⑦ 应用落盘
范围固定为项目默认层（非 Git 项目也如此）；不支持工作树差异的控件直接禁用。统一指令/宿主加载规则（AGENTS 与 CLAUDE 共存语义）⛔ AIL-117 未做，不静默改写用户已有的 AGENTS.md/CLAUDE.md。

⑩删除未托管 Skill（两步确认 + 归档可恢复）

UI 扫描区条目 →「删除…」API /api/project/delete-skill 两段：preview 发令牌+指纹 → execute 校验后归档落盘 data/project-archive/<ts>-<名>/（可手动移回）
点删除→ 预览影响（列出将删内容）→ 「继续：输入名称确认」→ 输入目录名→ 名称一致？
└─ 是 → 服务端校验：令牌单次有效 · 指纹一致（目录被换过则拒）· 路径不穿越 · 非项目根 → 归档并移除
守卫全绿：名称错零写入；令牌重放/重启后失效；目录内容被替换后拒绝执行；符号链接只摘链接不碰目标；项目根/穿越路径直接拒。

⑪MCP（现状：共享定义引用，只读）

UI 项目页 · MCP 页签API /api/resources/mcp-detail（服务端掩码，$ENV: 引用约束）
引用共享 MCP 定义→ 详情只读展示（掩码）→ apply 随计划写入宿主配置
⛔ 密钥安全托管/更换/作用域（AIL-116）← 等安全设计评审：Keychain vs 加密文件等，未评审不实现

⑫Agent / 其他资源（能力矩阵与禁选一致）

UI 项目页 · Agent / 其他资源页签 · 页头说明 + 折叠的「加载方式」参考表API /api/capabilities · /api/resources
进页签→ capabilities 首次即加载→ 宿主支持该类型？
├─ 原生支持（如 claude×agent）→ 可勾选
└─ 需生成入口 → 说明「AILoom 生成到宿主配置」；不支持 → 禁选+原因，矩阵与选择器同一份事实
其他资源类型行渲染不抛错（移除/恢复继承在同页可用）；页签切换受脏状态保护。

⑬来源更新与故障恢复

UI 来源页（显式选择项目目标）· 资源中心警告 · 项目页失效引用行API /api/library/check-update · /api/collections/check+update · warnings 字段
来源检查更新→ 扫描发现异常链接？
├─ 仓内链接 → 放行　├─ 外逃/悬空 → 逐项 warnings 定位（不再整源拒绝 E3003）
└─ 更新 → 按来源更新快照；同步失败逐项目报告，不暗改其他项目
项目引用的来源条目没了？→ 失效引用仍显示（不消失）→ 可在项目内「解除引用」→ profile 无残留
非 Git 项目在作用域选择器同样可选；来源页部署状态需显式选目标，未选时明确提示而非拿隐式 currentTarget 猜。
