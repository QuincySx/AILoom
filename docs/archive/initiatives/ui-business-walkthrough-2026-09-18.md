# UI 与业务流程走查实施总纲

日期：2026-09-18。状态：AIL-099～109 已于 2026-09-19 按本总纲逐卡走查、修复并验收（Done）；证据见 [docs/evidence/ui-journeys-2026-09-19](../../evidence/ui-journeys-2026-09-19/README.md)。

## 用户应当看到的业务

全局资源中心管理资源库存和真实来源；导入不等于在所有项目启用。项目选择自己要引用的资源；保存配置不等于部署；预览并应用才修改明确的目标工作目录。宿主自行读取的全局/祖先配置不归项目开关绝对控制。

项目默认由该项目工作树继承，不是用户级全局配置；工作树覆盖只影响所选工作树。界面必须区分本层设置、继承来源、有效配置、磁盘部署与宿主验证状态。改变现有契约前先列接口影响，不能用文案假装后端已经支持。

## 现状证据（代码核对，不冒充真实 UI 验收）

- `src/console/ui/pages/projects.js` 已有宿主、Skill、MCP、Agent、Markdown 指令、预览与应用、其他资源入口。
- 资源页直接列全局目录，缺少清晰的“本项目已添加”与“从资源库添加”分离；逐行 enable/disable/inherit 保存不能代替正常添加/移除流程。
- 项目页选择通过 `api.select({root,...})` 写项目默认；工作目录选择与配置写入范围的区别不够清楚。
- 有效值被用于初始化开关，继承与显式选择容易混淆；`effective` 不等于文件已部署或宿主已加载。
- 全局资源分组及引用 Dialog 有未提交修改；Dialog 尚未完整构建/浏览器验收，不标 Done。后续执行者先核对工作区，不覆盖现有修改。

## 交互规则

| 场景 | 应有交互 | 写入边界 |
|---|---|---|
| 项目列表进入项目、打开完整配置页 | 跳转，保留明确项目上下文 | 无写入 |
| 添加 Skill/MCP/Agent、管理引用 | 真正 Dialog，搜索/选择/确认/取消 | 明确项目及范围的引用配置 |
| 编辑项目资料、局部参数 | Dialog | 仅所示对象 |
| 移除项目引用 | 确认 Dialog，解释继承与待清理 | 不删除全局源或别的项目 |
| 删除全局来源 | 引用影响确认；引用存在须处理 | 不删除外部维护原文件 |
| 长篇指令编辑、预览与应用 | 项目内专用页面/面板 | 保存与部署分步 |

## 统一验收门槛

- 每卡先写复现路径、预期行为、实际行为，再修复和复测。
- 使用隔离项目 A/B/C、多工作树、多来源和假秘密；不得改真实用户配置、读取真实凭据或执行来源脚本。
- 每条写入都验证：保存在哪里、影响谁、取消是否零写入、失败如何恢复、刷新/重启是否持久化。
- 每条 UI 路径保留真实浏览器截图、实际 API/文件差异和结果；单元测试与 mock 只作补充。
- 覆盖空/加载/失败/冲突/失联、重复提交、旧响应、键盘、390px 窄屏。
- `docs/cards.json`、`docs/BACKLOG.md` 与卡正文同步；没有证据不能因为旧卡 Done 而通过。
