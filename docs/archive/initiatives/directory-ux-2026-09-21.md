# 目录优先 Web 整理 · 2026-09-21

## 本轮范围

根据 Orca 实际页面走查和当前 projects.js/API 结构拆卡。只规划，未修改产品实现，未承诺已经修好。
上轮浏览器已观察到：web 视图与项目级 Markdown 文案冲突；子目录按钮仍称工作树；高级入口丢项目上下文；本地资源与来源空状态分裂。
代码核对发现：diffOf 只比较项目默认与当前层，扫描及部署状态没有统一采用所选目录。继承缺陷需要隔离夹具复现，不能将静态发现写成已通过浏览器反例。

线稿总览：[HTML](../../design/wireframes/directory-ux/index.html)；每张卡内也有独立文本线稿。
旧 [business-logic.html](../../design/wireframes/business-logic.html) 保留作历史业务参考；本轮目录导航和范围表达以新卡为准。

## 用户主流程

打开项目 → 选择工作目录（多工作树时）→ 选择实际目录 → 看资源 → 添加/停用 → 预览 → 确认应用。
项目共享设置是另一明确入口，不与“当前目录”混在一个下拉框里。
非 Git 知识库同样适用，不搬文件、不初始化 Git、不上传知识库。

- “当前目录”是操作目标，不是新的 workspace 数据实体。
- 全局中心保存可复用资源；项目/目录保存引用与覆盖。
- 继承自动计算，行内说明真实来源；停用、清除覆盖、删除文件是不同动作。
- 项目根目录的日常操作默认针对当前工作目录；影响所有工作树的设置须进入项目共享设置。非 Git 根仍适配现有项目默认存储，不无故迁移。
- 子目录改动可能影响其下级继承目录；所有确认窗要按真实解析和宿主部署能力表述范围，不能笼统承诺“绝不影响其他目录”。
- 本轮维持“保存配置不等于写入宿主文件”，仍需显式预览应用。
- 不扩展 Agent Hub，不重写流程工作台，不改变 store 的物理布局。

## 组件与服务分工

| 责任 | 建议落点 | 约束 |
|---|---|---|
| 单一目标快照/过期保护 | 现有状态模块或小型 targetContext 模块 | 不为每页重复维护 scope；写入冻结快照 |
| 目录浏览/选择 | scopePicker 拆分或 DirectoryPicker | 只发选择事件，不保存配置 |
| 目录面包屑/范围说明 | ProjectTargetBar | 显示用户名称与路径，不泄露内部层枚举 |
| 资源行/来源/部署状态 | 共享 ResourceRow | effective 是生效事实；磁盘状态另查 |
| 添加与内联导入 | resourcePicker + importDialog | 同一 Dialog 分步骤，保留返回状态 |
| 项目共享设置 | 项目内独立路由 | 明确全项目范围，保留返回目录 |
| 预览与结果 | PlanPreview + JobPanel | 复用任务协议，不重复发明计划 |
| 来源组/引用 Dialog | collectionsPanel + resourceReferences | 真实来源为主，迁移渠道为辅 |

以上新增名称是设计建议，不假定仓库已有这些文件。框架、样式 token、基础组件优先复用。
服务端能力缺口必须有契约及测试，不可仅用前端拼路径掩盖。

## 给执行 Agent 的任务说明

> 先读本总纲，再逐卡执行 AIL-121～128，每张卡按内嵌线稿、顺序步骤、异常分支和验收完成。先检查并保留当前工作区改动；不要重置，不提交用户未要求的 Git 操作。
> 先复现目标/继承问题，再做组件，最后组装页面。不要只换 CSS，不要给正常用户增加配置层选择。
> 使用两个非 Git 知识库和 Git 双工作树隔离夹具。每卡提供真实浏览器截图、API 目标与文件断言；取消零写入，失败如实呈现。
> 线稿未画出的加载/空/失败/失联/未授权/草稿/部分成功状态也要覆盖。卡片验收没通过就不能标 Done。
> 不动用户真实知识库，不安装新 UI 框架，不展开 Agent Hub；发现需要改变产品语义时先记录差异，不静默扩大范围。

## 线稿使用规则

HTML 是静态评审板，示意按钮不执行真实操作；只有卡片导航可点击。每卡的文本线稿与 HTML 来自同一内容。
实现可以调整视觉细节，但不能改变目标、导航、确认步骤、危险动作边界。实现后用同一路径/状态截图对照，而不是仅核对颜色。
