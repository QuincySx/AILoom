9. 修复卡从真实入口重现问题，再补回归验证。纯函数/fake provider 测试只证明其覆盖层，不能代替要求的 CLI、宿主、跨进程或真实外部验收。记录修复前后实际行为、代码版本和证据位置；不要复制旧完成记录、旧测试次数或仅引用测试名称。

## 状态含义

- Backlog：待领取或已退回；尚未通过本轮必需验收。
- In progress：已由具名执行者领取并在实施/验收。
- Blocked：明确列出未满足的依赖、环境或授权，以及解除条件；不是伪装成完成的方式。
- Done：本卡约定的全部必需交付有实际证据；设计卡只代表设计完成。任意新增反例推翻验收时重新开放。
- Superseded：交付物已被后续改动删除或取代，原验收无法再复核；不计入完成，后继能力由取代它的卡负责验收。

勾选框就是验收依据：交付记录不能替代勾选。关卡时逐项把有证据的验收项改为 `[x]`，并在交付记录中写明证据位置；`python3 scripts/docs_check.py` 会列出仍有未勾项的 Done 卡。

原始依赖字段描述接口/功能关系。当前存在且经核实的接口可复用；依赖卡正在返工不意味着删除已实现功能。依赖实际不可用时停止相关验收并记录阻塞，不能用空实现补齐。所有卡的最终集成结论仍以本轮链路验收为准。

## 公共实施规则

- 先单 crate、清晰模块；模块路径是职责建议，不是强制新增文件清单。
- 统一 Config/Resource/Workspace/Revision 类型；适配器只做能力声明和渲染，文件写入统一经过同步器。
- 外部进程用参数数组，固定cwd，检查退出码；禁止把资源字段拼成shell命令执行。
- 所有机器根目录可注入，测试使用临时目录和本地裸仓；禁止测试污染真实宿主配置。
- 未支持的宿主能力明确报错或标记 unsupported，不静默降级到全局。
- 资源分发、宿主发现、Agent使用分别验收；自动化测试无法代替真实宿主发现记录。
- 新依赖应解决本卡明确需要；避免为未来需求增加通用框架。
- 不主动发布npm包、不推公开仓库；提交/外部写操作依照当前执行环境和用户授权。

## 测试分层

纯解析与选择→fixture单测；文件和事务→临时目录故障注入；Git→本地裸仓端到端；宿主发现→版本固定的人工或受控集成测试；报告/隐私→精确字段断言；看板→API一致性及浏览器基本交互。
