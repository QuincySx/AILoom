# 实现 AI 工作说明

## 领取一张卡

1. 阅读 README、CONTEXT、SCOPE、CONTRACTS 和目标卡。用户最新指示优先。
2. 看依赖完成记录和实际代码；Backlog 依赖不能当成已存在的 API。
3. 本仓库可能同时有人工作，不回滚他人的修改。只拥有目标卡的职责，共享接口变更先查调用者并同步文档。
4. 将卡片与 cards.json 状态改为 In progress；说明本次交付及验证路径。
5. 完成最短真实链路，再覆盖本卡指定错误路径。不要用伪造成功的 TODO、空 handler 或无条件 Ok 来绕过功能。
6. 运行变更对应测试与 Rust 基础检查，写入实际结果。不得把参考项目测试结果写成 AILoom 结果。
7. 更新卡片完成记录和 cards.json；依赖缺失用 Blocked，并写明具体缺口和解除条件。文档设计卡可以无代码完成，产品能力卡必须有真实实现。

## 公共实施规则

- 先单 crate、清晰模块；模块路径是职责建议，不是强制新增文件清单。
- 统一 Config/Resource/Workspace/Revision 类型；适配器只做能力声明和渲染，文件写入统一经过同步器。
- 外部进程用参数数组，固定cwd，检查退出码；禁止把资源字段拼成shell命令执行。
- 所有机器根目录可注入，测试使用临时目录和本地裸仓；禁止测试污染真实宿主配置。
- 未支持的宿主能力明确报错或标记 unsupported，不静默降级到全局。
- 资源分发、宿主发现、Agent使用分别验收；自动化测试无法代替真实宿主发现记录。
- 新依赖应解决本卡明确需要；避免为未来需求增加通用框架。
- 不主动发布npm包、不推公开仓库；提交/外部写操作依照当前执行环境和用户授权。

## 测试分层

纯解析与选择→fixture单测；文件和事务→临时目录故障注入；Git→本地裸仓端到端；宿主发现→版本固定的人工或受控集成测试；报告/隐私→精确字段断言；看板→API一致性及浏览器基本交互。

## 可复制的派工提示

> 实现 docs/cards/AIL-XXX.md。先读 README.md、CONTEXT.md、docs/CONTRACTS.md 和 docs/IMPLEMENTATION-GUIDE.md，并核对依赖完成记录。只实现本卡范围，遵循现有类型与模块，不回滚其他人的修改。按卡片场景验证，记录真实结果并更新卡片及 docs/cards.json。遇到未定义的高影响语义先列出冲突，不自行用全局覆盖或伪成功补齐。
