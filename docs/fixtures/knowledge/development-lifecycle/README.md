# 开发知识编纂验收样例

全部内容均为虚构项目 ParcelDesk 的测试资料，不代表 AILoom、参考项目或任何真实供应商。用于核对默认提示词实际产物；不运行样例代码或安装依赖。

## 输入

编纂任务的 repository 指向本目录 `repository/`，knowledge_directory 指向 `knowledge/`。source_documents 为 `knowledge/notes/` 下全部七份文档的相对路径；previous_report 指向 `knowledge/docs/organized/sample.md`。source_origins 将 `notes/05-experiment.md` 标为 `feature/parallel-dispatch` 分支、未提交，其他资料标为 `main`；提交未提供。其余清单字段与应用一致，focus 使用内置默认值。评估者另收到 review_report 指向实际新稿。

review_report 可在隔离目录暂存；评估清单可显式给出 report_destination 为 `docs/organized/generated-sample.md`（相对于知识库），来源相对链接按目标发布目录核对。目标稿尚不存在属于正常候选状态；必须区分临时存放与发布位置，同时检查实际原文存在，不能只因草稿位置不同判链接坏掉。

本 README 和 `updates/` 不属于第一轮编纂输入，也不作为虚构项目的原始证据。评估者可以读取本页验收问题。第二轮将 `updates/replay-resolution.md` 复制到隔离知识库 `notes/08-replay-resolution.md` 并加入清单，previous_report 改为第一轮产物。测试时复制到 `target/` 下独立目录，不覆盖此处固定输入。

可用真实本机 CLI 的只读入口执行，模板见 [整理提示词](../../../../src/knowledge/res/organize-wiki.md) 和 [独立评估提示词](../../../../src/knowledge/res/review-wiki.md)。记录实际工具版本、输入摘要、输出与评估；生成器不应读取本页验收答案。格式或关键词测试不能代替这项检查。

## 第一轮必须核对

| 问题 | 原文支持的答案或边界 |
| --- | --- |
| 为何早期串行而非并发/队列？ | 供应商只允许一个在途请求，团队无人值班；直接并发被否，队列延后，接受吞吐低和阻塞的代价；不是“作者水平不足” |
| 现在用什么？旧选择当时错了吗？ | v1.0 改队列，原因是外部配额与内部幂等/运维条件变化；旧选择当时合理。保留旧理由、代价和变化条件 |
| 十路并发是否已经上线？ | 未合并实验，不能写成主分支现状；主代码是队列、三次重试 |
| 已发货能自动退款吗？超时算失败吗？ | 已发货转人工退货；超时是状态不明，先查供应商，不得据此标失败或自动退款 |
| 业务流程和开发流程是否分清？ | 支付/排队/发货是业务流程；改契约、加测试、验收与试运行是开发流程；不能把改代码步骤当业务流程 |
| 回补能自动重放吗？ | 两份同范围便签冲突，缺少裁决；列双方和核对方法，不能按文件编号或多数意见选择 |
| page size 为什么是 37？ | 代码只能证明值为 37，动机未记录；不能沿用旧报告编造的供应商限制 |
| 自检是否表示验收通过？ | 不表示；新稿标 unreviewed，明确未执行测试、未获独立评估 |
| 旧稿如何纠错？ | 撤回“并发已全量”“超时直接退款”“37 是供应商上限”的确定断言，证据回到原文；沿用三个既有主题 ID，合并时保留旧入口 |

所有输入均应在来源目录中有处理交代；核心问答需能定位主题和支持证据，不能只在 sources 列标题。需保留缓解与根治、外部/内部约束，以及尚未记录或未完成的部分。检查原文未被改写、引用能定位、没有指向被覆盖报告的自引。

同时检查精简：同一事实不应在核心表格、背景、概览、问题和维护建议中反复展开。少量短记录不能被扩成万字说明书；可以合并回答同一问题的知识，保留原主题入口、必要理由和证据。压缩不能牺牲以上问答。

## 第二轮必须核对

新决策明确裁决回补冲突：仅对“已排队且持有效幂等键、经核对未发货”的任务允许自动重放；状态不明仍转人工。它替代旧的两种笼统便签，旧争议及当时证据保留，不能写成以前从无争议或所有任务均可重放。

该文件是已批准、尚未实现的决策；主代码仍无回补实现。稿件必须分清目标规则与当前实现，不能宣布代码已完成或测试已通过。沿用第一轮相关主题入口，只更新有新证据的知识；未知的 37 动机仍未知。
