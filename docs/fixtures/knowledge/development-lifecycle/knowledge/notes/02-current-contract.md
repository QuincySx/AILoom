# v1.0 业务与派单契约

2026-10 的维护阶段决策：供应商放开到每租户最多十个在途请求，内部已具备幂等键、积压告警和轮值。v1.0 采用队列，替代 v0.1 串行派单；原因是条件变化，不是此前错误。十是上限，不表示必须并发十路。队列代价是需要维护积压和重放语义。若幂等无法保证或告警失效，需重审并发与重放，不能盲目扩容。

业务流程：待支付 → 已支付 → 待派单 → 已发货。供应商创建响应超时表示状态不明，不等于创建失败；必须先按派单 ID 查询供应商。已发货订单进入人工退货流程，不能自动退款；发货前取消由取消流程处理，本记录未定义其完整细节。

当前标准派单任务对限流响应最多重试三次；此数字不适用于状态不明的请求。模块分工：支付确认只负责入队，dispatch 模块负责创建和查询；账务模块不得仅凭创建超时触发退款。
