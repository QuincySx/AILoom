## 与需求尚未对齐

1. **跨项目共享语义**：不同项目关联同一个知识库根，当前共用根下 learnings/docs，能互相检索；仅恢复配置按 project UUID 分开。已经实际验证第二项目可检索第一项目的两条知识。是否改为“默认按项目隔离 + 显式共享内容”仍待用户选择，未擅自迁移数据。
2. **网页范围**：当前知识库设置页只有保存位置、迁移/恢复和恢复配置快照。没有知识列表、内容阅读编辑、检索及归档管理入口。CLI 有 save/recall/maintenance，不代表网页具备同等完整流程。
3. **Skill 产物目录**：规格、任务、ADR、领域词汇、原型的路径规则尚未实现；前面给出的目录表是方案，不能当作已有功能。
4. **Git 语义**：选择 Git 目录只展示仓库信息并记录可迁移来源，不会自动提交或推送。旧的显式 knowledge sync 独立配置远端/分支，网页当前没有同步操作入口；不能将“保存在 Git 内”展示为“已同步”。

## 本轮修改

`KnowledgePanel` 在迁移或恢复请求失败时清除旧预览与确认按钮状态，保留用户输入；下一次提交重新预览。未改变知识库布局、共享语义或同步策略。

## 全量回归与后续修复

初次全量回归为 458 项通过、10 项失败、1 项忽略（cargo-test.log）。排查后修复：

- CLI personal sync 恢复默认当前目录；应用任务统一使用实际工作区根记录验证与撤销路径。
- CLI 同步结果补回 failed 与 pending_journal，保留具体失败信息。
- Git 来源快照物化加锁，避免并发删除同一暂存目录。
- 直接关联的外部 Skill 拒绝目录外或悬空链接，其他资源仍可独立导入。
- 三处旧测试对齐已实现行为：简化后的引导文案、忽略单个不安全资源但保留安全资源、Claude 入口 fallback 下仍有效的写入故障注入。

修复后的全量 Rust 回归 468 项通过、0 失败、1 忽略（final-cargo-test.log）。随后新增子目录部署与真实撤销回归，单项通过，并复跑相关集成测试（subdirectory-test.log）。前端组件测试 8 项通过。代码复查通过。
