# 2026-09-20 控制台全页面梳理：前端 × 后端 × 切面

背景：用户反馈「完全不是给人用」「要按切面切、挨个页面梳理」。本文是全量梳理与设计规则，
是后续 UI 改造的执行依据。基于 HEAD + 当前未提交修改的真实代码与运行中的 8646 实例。

## 一、系统到底是什么（一句话）

用户把散落本地的 AI 资源（技能/规则/文档/子代理/MCP 配置）登记进资源库，
再按项目挑选、启用，由 AILoom 写入项目目录供 Claude Code / Codex CLI 读取。

核心链路只有一条：**入库（资源库）→ 引用（项目选择）→ 部署（写入项目目录）→ 生效（宿主新会话）**。
每个页面都应该是这条链路上的一站，其他内容都是辅助。

## 二、五个切面（跨页面设计规则）

### A. 状态切面——任何资源在任何页面，只允许一套状态词
- 资源四态：`未启用`（灰）/ `已启用`（绿）/ `已停用`（灰）/ `来源不可用`（红）
- 部署三态（次要小字，不抢主状态）：`已部署` / `待更新` / `未部署`；异常态 `部署不一致` / `状态未知（重试）`
- 禁词：~~本层~~、~~有效~~、~~期望部署~~、~~trace~~、~~期望内容~~。用户语言：作用范围、当前状态、待生效
- 生效语义一句话：**改配置 ≠ 生效；生效 = 预览并应用 + 宿主新会话**

### B. 动作切面——每个写操作都有统一的三段反馈
- 改前：危险动作（停用/移除/删除）必须有确认，说明影响范围与恢复方式
- 改中：按钮禁用 + 行内 busy，禁止重复提交
- 改后：一句话结果（成功/部分失败+哪个失败/失败+怎么重试）；来源提示不覆盖操作反馈
- 部署类动作（plan/apply/undo）集中在「预览与应用」和「操作记录」两处，不散落

### C. 术语切面——内部模型不出现在一级界面
| 内部词 | 用户词 |
|---|---|
| 本层 / repo_default / worktree_override | 作用范围：项目默认 / 仅当前工作树 |
| 有效：期望部署 | 已启用（未生效）→ 用状态徽章表达 |
| 恢复继承 | 恢复继承（清除这里的设置） |
| 计划指纹 / revision / base_commit | 不出现（放 title/详情） |
| 资源 ID（personal/skill/personal/x） | 行 title 提示 |

### D. 导航切面——主导航三站，其余全部收编
- **项目**（配置发生地）/ **资源中心**（入库与来源）/ **操作记录**（审计与撤销）
- 重叠页面处置见第三节 S1–S4

### E. 文案切面——每页一句话导语；空态=一句话+一个主操作；错误=发生了什么+怎么办
- 删掉所有超过两行的解释性段落；细节放 title / 详情弹窗 / 帮助图标

## 三、页面清单（前端页面 ↔ 后端数据 ↔ 处置）

### 1. #/projects 项目列表 —— 保留
- 数据：`GET /api/state`（注册表+项目元数据）
- 动作：新建项目（`/api/fs/approve`+`/api/repo/discover`+`/api/projects/metadata`）、搜索/分类/类型过滤
- 问题：无重大问题；「浏览…」无头环境禁用（已说明）
- 处置：保持

### 2. #/projects/:id 项目配置（7 页签）—— 主战场，重构中
- 数据：`/api/effective`（状态）+ `/api/resources`（可用资源+来源告警）+ `/api/deploy-status`（磁盘）+ `/api/capabilities`（矩阵）+ `/api/project/scan-skills`（本地扫描）
- 动作：`/api/profile/select`（引用三态）、`/api/jobs/plan`+`apply`（部署）、`/api/project/delete-skill`（本地删除）、`/api/profile/instructions`
- 已完成：状态徽章化、扫描去重、能力矩阵折叠人话化、移除双语义、部分失败报告
- 遗留问题：
  - P1 **改完配置无全局提醒**：生效要自己发现「预览与应用」页签 → 加常驻横幅「N 项修改未生效 → 去应用」（本轮实施）
  - P1 Agent 页签每行重复长说明 → 移到页头（本轮实施）
  - P2 其他资源页每行重复类型说明 → 折叠（本轮实施）
  - P2 七个页签偏多：「其他资源」低频可折叠进「更多」；「预览与应用」可改为页签+横幅并存（保持，横幅已解决发现性）

### 3. #/library 全局资源中心 —— 保留，作为「入库」唯一入口
- 数据：`/api/collections`（来源+资源+更新状态+warnings）、`/api/library/list`（个人副本）、`/api/library/resource`（读写）
- 动作：导入（ImportDialog：本地/Git/skills.sh）、检查更新、更新、来源移除、CC Switch 迁移、个人副本编辑/删除
- 问题：同一页有「来源管理+个人副本表+编辑器」三块，信息密度高但职责一致
- 处置：保持；后续把 sources 页的更新职责并入（S2）

### 4. #/sources 更新中心（隐藏路由）—— 并入 library（S2）
- 数据：`/api/library/sources`、`/api/collections`、`/api/deploy-status`
- 问题：与 library 职责重叠（更新检查两边都有）；「部署状态」块依赖显式目标选择，价值低
- 处置：S2——把个人副本更新检查并入 library，页签下线

### 5. #/scopes 仓库与作用域（隐藏路由）—— 下线（S1）
- 数据：`/api/state`、`/api/effective`、`/api/profile/select`、`/api/preview/repo-default`
- 问题：**这是旧版项目配置页**，与 projects/:id 功能重叠（选目标+三态+预览应用），且交互更原始
- 处置：S1——下线路由；「子项目等高级范围…」链接改为指向项目内（或临时保留路由但不再从项目页链接）

### 6. #/tasks 操作记录 —— 保留
- 数据：`/api/jobs`、`/api/jobs/undo`
- 处置：保持；undo 冲突提示已有

### 7. #/onboarding 首次设置（隐藏路由）—— 保留但弱化（S3）
- 数据：approveDir/repoDiscover/select/effective/resources
- 问题：与项目页重复的第二套配置流；批量保存已复用 114 部分失败行为
- 处置：S3——保留给空状态引导（无项目时项目列表给入口），完成后不再出现

### 8. #/workflows 流程工作台（隐藏路由）—— 冻结（S4）
- 数据：`/api/workflows*`、`/api/library/list`
- 处置：S4——非急用版范围；保持可访问不进主导航，不再投入

### 9. #/overview、#/samples —— 下线（S4）
- overview：`/api/jobs` 的重复展示；samples：开发样例
- 处置：S4——从路由表移除（samples 保留文件供开发）
