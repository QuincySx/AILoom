## 按顺序实现

1. 汇合来源合集与个人库的展示模型，按真实来源身份分组；仓库多个 Skill 一组，本地资源单独一组，不因 URL 拼写差异随意合并不同分支/管理模式。
2. 主行用 Skill 名称和说明，内部 resource ID 放详情；Git URL/SSH、版本、更新状态在组头，CC Switch 仅作导入历史次要信息。
3. 空状态基于全部可见资源；已有本地资源时不再显示整个中心为空或仅强调“导入第一个来源”。
4. 检查全部更新与更新分开：检查不改内容，更新先展示版本差异、冲突及受影响项目；本地无远端条目不可提供虚假的检查更新。
5. 管理项目引用必须 Dialog；展示直接引用/继承生效差异。继承行引导选择在该目录停用或去来源层管理，不能删除一个不存在的直接引用。
6. 全局移除来源与项目停用使用不同危险确认；受影响引用和失败处理沿用已有能力，禁止静默级联删除用户文件。
