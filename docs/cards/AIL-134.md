## 背景

结果文本走 stderr 日志、人类模式打印原始 JSON 或 Rust Debug、clap 错误在 `--json` 下不是 JSON、doctor 失败仍退出 0。

## 顺序步骤

1. 结果摘要一律 stdout，`[ailoom:info]` 只用于过程日志。（为 report / packages / code / knowledge / collection / members 设计人类格式已移入 AIL-135。）
2. `Cli::try_parse()` 捕获 clap 错误，`--json` 下映射为 E0001 JSON；裸跑 `ailoom` 的 help 走 stderr 或 exit 0（二选一并写入契约）。
3. status / doctor 去掉 Debug 格式；doctor 有失败项时返回非 0（保留 `--no-fail`）。
4. plan 的人类输出区分同一文件的多个片段。

## 必须验收

- [x] 主路径命令（init / sync / status / doctor / library / personal）的人类模式结果走 stdout 且无 Debug 格式；`--json` 参数错误与裸跑行为有测试。
- [x] doctor 退出码有测试。

## 交付记录

负责人：Claude Code（2026-10-01）。

- **结果走 stdout**：source / init / sync（含 recover）/ contribute / hooks / uninstall / contribute-self 的结果摘要，从 `[ailoom:info]` 日志改为写到 stdout；同时去掉了 init、sync recover 中的 `{:?}` Debug 输出。
- **参数解析错误**：`main` 改用 `Cli::try_parse()`。`--json` 模式下参数错误输出 E0001 错误 JSON（带 `schema_version`，只取 clap 的错误段落），退出码 2；`--help`、`--version` 行为不变。裸跑 `ailoom` 的帮助改走 stderr，退出码保持 2。
- **status / doctor 格式**：status 的项目、角色、额外宿主改为逗号列表；doctor 的检查名和详情不再带引号或原始 JSON。
- **doctor 退出码**：新增 `--strict`，有失败项时退出 10；默认行为不变，避免破坏现有调用方。
- **plan 重复行**：plan 的人类输出给同一文件的多个片段附上 `[fragment:<id>]` 一类后缀，以便区分。

验证：`tests/cli_output_contract.rs` 覆盖参数错误 JSON、裸跑、help、doctor 默认与 `--strict`、init/sync 结果走 stdout、status 无 Debug，以及 library/personal 人类输出非空。
