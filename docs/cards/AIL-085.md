## 按顺序执行

1. 只允许 services 模块 fetch；统一会话 header、JSON 解析、HTTP 错误、网络/超时、AbortSignal，不把认证 Token 放日志或持久存储。
2. 按 repo/profile/library/workflow/jobs 分服务，方法接受显式 target 与 revision；在本卡契约表列出实际请求字段，不能随意拼 shell/CLI 参数。
3. 规范 ApiError(kind,status,code,message,fieldErrors,currentRevision,retryable)，区分 409、401/403、校验、网络断开和服务器失败。
4. GET 可由页面明确重试；写操作不自动重放，只有已定义幂等键的任务请求复用同一个键重试。
5. 用请求序号与 AbortController 支持切目标/离页后取消，未能取消的过期响应仍由状态层丢弃。
6. 提供假的 transport 用于错误组件开发；实际页面以真实 services 注入，禁止把 mock 作为生产回退。

- 组件输入为 props，输出为 onXxx 事件；基础组件不调用后端，业务组件由 services 注入；页面只负责组装、路由和状态绑定。
- 先核对依赖接口，不用生产 mock、空回调或硬编码成功补齐缺失 API。组件样例可用明确的 fixture，真实页面必须接真实 API。
- 你不是独自工作，不回滚他人修改；本卡拥有上列模块，共享入口按依赖顺序修改并记录交接。
- Token/基础组件先完成；不得在每个页面各写一套按钮、弹层、fetch、冲突处理或任务轮询。保留现有单二进制离线使用，不擅自引入 CDN/重型运行时。
