## 按顺序执行

1. 建立 primitive 与 semantic 两层 CSS variables：背景/表面/文字/边框/强调/成功/警告/错误/焦点，组件只消费 semantic Token。
2. 固定间距 4/8/12/16/24/32、字号 12/14/16/20/24、行高、圆角、阴影、控件高度和容器宽度；具体色值集中定义并测对比度。
3. 定义侧栏+顶部目标栏+内容区布局；窄屏导航折叠，表格区域横向滚动，表单/弹层不溢出视口。
4. 完成按钮、输入、状态色、字体与布局的静态对照样例；中文标签、长路径和长 ResourceId 都要显示。
5. 定义 focus-visible、disabled、pending、错误辅助文本和 reduced-motion；状态同时使用文字或图标，不能只靠颜色。
6. 不加入未确认的点赞业务或 Token 用量统计；这里的 Token 专指设计变量。

## 必须验收

## 交接与约束

- 组件输入为 props，输出为 onXxx 事件；基础组件不调用后端，业务组件由 services 注入；页面只负责组装、路由和状态绑定。
- 先核对依赖接口，不用生产 mock、空回调或硬编码成功补齐缺失 API。组件样例可用明确的 fixture，真实页面必须接真实 API。
- 你不是独自工作，不回滚他人修改；本卡拥有上列模块，共享入口按依赖顺序修改并记录交接。
- Token/基础组件先完成；不得在每个页面各写一套按钮、弹层、fetch、冲突处理或任务轮询。保留现有单二进制离线使用，不擅自引入 CDN/重型运行时。
- 完成真实操作验收再勾选；同步卡头、cards.json、BACKLOG 与本轮索引，相关父卡仍需原始验收。
