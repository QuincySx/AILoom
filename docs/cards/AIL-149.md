## 背景

AIL-110 原写「默认登记原目录，不移动正文；内部知识库托管存储含义未确认，不擅自实现」，实际实现却是新项目知识库默认放在 AILoom 数据目录（托管），并提供整体迁移。2026-10-02 用户确认保留现状：**默认托管 + 可迁移**属于产品范围。本卡为这两项能力补齐范围与验收。

## 范围

1. 默认位置：`<data_root>/knowledge/projects/<项目 ID>`。添加项目时也可选项目内目录、外部普通目录、外部 Git 仓库（含子目录）。
2. 迁移：预览 → 复制 → 逐文件核对 → 切换登记，执行必须带预览返回的 `expected`。原位置保留为备份；同一知识库下的项目一起切换；迁移记录写入 `<data_root>/knowledge/migrations/`。
3. 安全边界：目标非空、相同或嵌套、知识库含符号链接、预览后内容变化、超过上限时拒绝，登记不变，目标不写入。

## 必须验收

- [x] 迁移保留内容，召回与保存跟随新位置，原位置作为备份保留：`folder_move_preserves_content_and_cli_read_write_location`
- [x] 目标非空、嵌套、预览过期时拒绝，原位置与目标目录保持不变：`conflicts_stale_preview_and_nested_paths_do_not_switch`
- [x] 符号链接在复制前拒绝：`symlinks_are_rejected_before_copy`
- [x] 共享知识库迁移时所有项目一起切换，不混入其他项目：`shared_knowledge_moves_all_project_links_without_mixing_other_projects`
- [x] 迁移后 Git 同步往返，以及网络失败时本地迁移照常成功：`git_sync_round_trip_after_move_preserves_other_paths_and_reports_conflicts`、`migration_and_sync_are_one_flow_with_local_success_on_network_failure`
- [x] 网页端迁移要求目标在已批准目录内，并走同一绑定：`console_uses_same_binding_and_requires_approved_destination`
- [x] 迁移记录带 `schema_version`，完成后状态为 `switched`：`move_writes_versioned_switched_record`（2026-10-02 新增）
- [x] 用户文档写明默认位置、迁移流程与拒绝条件：[项目与知识库恢复](../guide/KNOWLEDGE-PORTABILITY.md)「保存位置与迁移」
