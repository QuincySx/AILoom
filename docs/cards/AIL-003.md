## 目标与交付

从 cwd 向上发现项目；区分 project anchor 和 workspace root；定义全局缓存与工作区状态目录。

## 验收标准

- [ ] 从子目录和两个 Git worktree 得到正确绑定
- [ ] 资源写当前 checkout
- [ ] 共享缓存不串绑定
- [ ] 符号链接、空格路径及路径碰撞有测试
- [ ] 识别失败不能静默写全局。

## 实施边界

- 本卡限定以上交付；新增范围先更新卡片及依赖。
- 参考实现用于理解机制，AILoom 的格式与行为以 AIL-001 契约为准。
- 宿主工具路径、格式和 Hook 能力须在实施时按官方文档与真实版本核实。
- 完成后记录验证命令、结果、支持版本及未覆盖项，再改为 Done。

## 文件职责（建议布局）

src/workspace.rs、src/paths.rs、tests/workspace.rs。已有等价模块时复用，不为匹配路径复制逻辑；共享类型只有一个定义。

## 输入与输出

输入：cwd 与可注入的数据根；输出：repository_anchor、workspace_root、workspace_id、binding_path、cache_root。

## 实施步骤

1. 先解析显式根再向上识别声明/Git根。
2. 通过 Git 子进程参数数组得到绝对路径。
3. repo anchor只用于共享缓存。
4. workspace身份含当前checkout路径。
5. 无Git目录需要显式声明才绑定。
6. 所有数据根可注入。
7. 处理路径别名与平台大小写语义。

## 必测场景

- [ ] 根目录与深层子目录得到同一workspace。
- [ ] 主checkout和linked worktree共享repo anchor但workspace_id不同。
- [ ] 两个worktree绑定不同项目互不影响。
- [ ] 含空格中文路径可用。
- [ ] 找不到根返回错误而非用户级默认。

## 明确不做

- 不能只以 basename 或路径替换字符作为ID。
- 不能把主checkout作为worktree的资源目标。
- 不能一律把路径转小写。
