## 目标与交付

将脱敏计数和可选摘要发布到专用统计分支/位置；成员维度增量上报、生成团队周期汇总。

## 验收标准

- [ ] 重试不重复计数
- [ ] 多设备身份有规则
- [ ] 上传可关闭
- [ ] 离线失败后可补传
- [ ] 资源发布与统计提交互不污染
- [ ] 来源缺失在汇总中可见。

## 实施边界

- 本卡限定以上交付；新增范围先更新卡片及依赖。
- 参考实现用于理解机制，AILoom 的格式与行为以 AIL-001 契约为准。
- 宿主工具路径、格式和 Hook 能力须在实施时按官方文档与真实版本核实。

## 文件职责（建议布局）

src/reporting/、src/commands/digest.rs、tests/reporting.rs。已有等价模块时复用，不为匹配路径复制逻辑；共享类型只有一个定义。

## 输入与输出

输入：成员/设备/workspace的聚合快照、上报开关；输出：独立报告存储和周期digest。

## 实施步骤

1. 为batch设置稳定幂等ID。
2. 按device/session保存累计值或增量watermark但不能混用。
3. 通过独立报告工作区提交精确路径。
4. 确认推送成功才推进checkpoint。
5. 只上报白名单字段。
6. digest标注时间范围、时区及缺失源。

## 必测场景

- [ ] 提交成功但响应丢失重试不翻倍。
- [ ] 两设备同成员可合并不互盖。
- [ ] 断网补传。
- [ ] 资源revision不被统计提交推进。
- [ ] 关闭上报不落远端。
- [ ] 默认报告无prompt/绝对机器路径/秘密。

## 明确不做

- 不宣称Git上报是实时总线。
- 不直接复用资源审核分支写统计。
- 不因上报失败清空队列。
