## 目标与交付

定义 Markdown frontmatter 和经验 ID；contribute 支持明确 project/shared 目标，验证来源及项目范围。

## 验收标准

- [ ] 项目 A 经验写 A
- [ ] 公共经验需明确选择
- [ ] 绑定多项目时要求指定目标，不静默变共享
- [ ] 标题/正文验证
- [ ] 提交失败保留草稿。

## 实施边界

- 本卡限定以上交付；新增范围先更新卡片及依赖。
- 参考实现用于理解机制，AILoom 的格式与行为以 AIL-001 契约为准。
- 宿主工具路径、格式和 Hook 能力须在实施时按官方文档与真实版本核实。
- 完成后记录验证命令、结果、支持版本及未覆盖项，再改为 Done。

## 文件职责（建议布局）

src/learning.rs、src/commands/contribute.rs、tests/learnings.rs。已有等价模块时复用，不为匹配路径复制逻辑；共享类型只有一个定义。

## 输入与输出

输入：文档、title/tags、--project或--shared；输出：稳定LearningId及贡献草稿/PR。

## 实施步骤

1. 解析frontmatter并验证UTF-8和正文非空。
2. 稳定ID不依赖标题。
3. 显式shared或一个project。
4. 仅有一个活动项目可使用该项目默认。
5. 多项目且缺目标时报错。
6. 保留出处引用。
7. 送交AIL-014审核路径。
8. 失败保留本地文档。

## 必测场景

- [ ] A经验只标A。
- [ ] 明确shared才能共享。
- [ ] 多项目不能静默共享。
- [ ] 重试同LearningId不重复创建。
- [ ] 非法namespace和路径拒绝。
- [ ] 引用外部绝对路径不作为可提交机器数据。

## 明确不做

- 不复制完整会话到经验文件。
- 不让角色决定经验归属。
- 不默认直接推主分支。
