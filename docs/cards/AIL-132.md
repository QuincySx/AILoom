## 背景

控制台错误只有 `{error}` 文本且直接拼 Display；非法 JSON 被当作 Null；未知方法返回 404；Mutex 中毒会连锁 panic；会话 token 出现在 URL 与日志中。

## 顺序步骤

1. 错误统一为 `{error, code, hint}`，前端按 code 分类；不再把 `[E….] … | context:` 原样给用户。
2. 请求体不是合法 JSON 返回 400；已知路径的不支持方法返回 405。
3. 锁统一 `lock().unwrap_or_else(|e| e.into_inner())` 或改用不中毒的锁；sync/apply 中的 unwrap 改为返回 E4004。
4. 启动 URL 与日志不再携带 token（或改为一次性交换）；`/api/events` 删除或统一鉴权。
5. 评估 AIL-112 预览与执行之间的替换竞态，必要时在归档前对目标加锁或做 rename-then-verify。

## 必须验收

- [x] 新增 API 测试覆盖错误结构、400/405、锁中毒后服务仍可响应。
- [x] 日志与 stderr 中不再出现 token。

## 交付记录

负责人：Claude Code（2026-10-01）。

- **错误结构**：新增 `Response::error`，业务错误返回 `{error, code, hint, context}`。`error` 只放 `Error.message`，`collection_response`、profile、草稿冲突等 46 处都已改用它。前端 `ApiError.data.code` 现在能拿到错误码，前端的分类仍按 HTTP 状态，按 code 细分留给 AIL-140 的文案统一处理。
- **400 / 405**：请求体不是合法 JSON 时直接返回 400。已知路径收到不支持的方法时返回 405，路径清单 `KNOWN_PATHS` 由单元测试 `known_paths_match_route_table` 与 `route` 分支保持同步。
- **锁中毒**：控制台的锁统一通过 `LockExt::lock_ok()` 获取，中毒后继续使用内部数据。`src/console/` 下已没有 `.lock().unwrap()`，只剩测试本身那一处；单元测试为 `poisoned_lock_keeps_serving`。
- **token**：`open_browser`、`ailoom web` 返回的 URL 和前台启动日志都不再带 `?token=`，页面的会话令牌仍由 `GET /` 注入。`/api/events` 同时接受请求头令牌。
- **AIL-112 竞态**：目录先 rename 进归档，在归档位置复核指纹，不一致就移回原处并返回 409；跨设备复制时，先核对副本指纹再删除原目录。
- **sync/apply 的 unwrap**：逐个核实，13 处都有前置的类型或非空检查，属于安全的不变量，本卡不改。

验证：`tests/console_api_contract.rs`（非法 JSON 400、错误方法 405、未知路径 404、错误结构不含 Display 文本），以及 console 系列测试全部通过。
