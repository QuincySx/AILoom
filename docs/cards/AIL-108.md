## 补充走查（2026-09-19 第二轮：次级页面一对一功能驱动）

首轮验收后自查发现五个次级页面只做了渲染级走查，按同一标准补齐：

- **#/scopes 仓库与作用域**：ScopePicker 选行切目标 → 有效配置表 → 「写入选择」（deploy-helper enable，profile 核对）→ 「预览各工作树影响（无写入）」→ 本页 生成预览/应用（产物写入所选工作树 a2）→ 恢复继承再应用（产物清理）。期间发现并修复：服务重启后从本页直接选目标时 `effective` 403（approveDir 缺失，批准根为内存态）——onTargetSelected 现随用户动作显式批准（ail108b-scopes-applied.png）。
- **#/sources 更新中心**：独立页面驱动「检查全部更新」逐源回显（已是最最新）、无可更新时「更新全部可用版本」禁用（ail108b-sources.png）。
- **个人副本编辑器（库页）**：点击行打开 → 修改保存（指纹更新）→ 外部改动磁盘后再保存 → 「文件已被外部修改…草稿保留在你的编辑器中」→ 删除确认（涉及作用域提示）→ 移入 library-archive（磁盘核对 3→1 文件、归档 2 文件）。期间发现并修复：库页两个 `[data-msg]` 选择器碰撞，编辑器的保存/冲突消息串位写到资源中心状态栏——改为 `data-edit-msg`（ail108b-copy-editor / copy-conflict / copy-delete-confirm.png）。
- **#/onboarding 六步向导**：从真实草稿状态续跑 1→6 全程（批准目录→识别→探测宿主→勾选资源→保存选择→预览→应用确认→完成跳转资源库），产物落盘核对；顺带验证草稿跨页面/重启持久化（ail108b-onboarding-step3 / preview / applied.png）。原生文件夹选择器（`浏览…`）在无头环境按设计禁用，需本机手动验证。
- **流程工作台文档流**：新建/打开流程 → 阶段绑定真实资源身份（align → bound）→ 记录输入版本（inputs 表）→ 产物写入 v1 → 编辑带版本前置 → v2 → dirty 确认（取消保留正文）→ 标记已复核 → 导出确认前置 + v2 内容落盘 + 覆盖自动备份到数据区 export-backups（ail108b-workflows.png）。绑定选项来自个人库（合集资源不在其列）为现状，已记录。
- 期间脚本时序类误报（toast 4 秒自hide、异步重渲染竞态）均以 API + 磁盘核对排除，未计入产品缺陷。
- 补充后回归：全站四档宽度溢出检查、current/grouped/design harness、`cargo test` 全量 43 套件保持全绿。
