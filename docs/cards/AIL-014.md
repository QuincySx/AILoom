## 目标与交付

本地修改变成变更集，独立分支提交；初版只适配 GitHub PR，其它 Git 源输出手动审核路径；pull 消费已发布 revision。

## 验收标准

- [ ] 用户能预览实际贡献内容
- [ ] 不提交机器数据
- [ ] 不改变业务仓库 checkout
- [ ] 远端冲突可重试
- [ ] 审核合并后另一工作区更新得到变更。

- 本卡限定以上交付；新增范围先更新卡片及依赖。

## 输入与输出

输入：预览过的资源变更集、base revision；输出：独立贡献分支和PR链接/手动审核提示。

## 实施步骤

1. scan仅允许共享资源字段。
2. 建立独立source工作区。
3. 变更集携带base revision和资源ID。
4. 校验最新远端避免覆盖。
5. 提交仅精确路径。
6. GitHub通过已配置CLI/API创建PR。
7. 记录变更集ID使失败重试复用。
8. pull更新到合并后的显式新锁。

## 必测场景

- [ ] 两成员修改同资源产生冲突。
- [ ] 网络失败保留本地变更。
- [ ] PR创建重试无重复。
- [ ] 本机binding/secret/log绝不能被stage。
- [ ] 业务工作区dirty文件和branch不变。
- [ ] 本地裸仓测试无需真实远端写入。

## 明确不做

- 不直接push默认分支。
- 不假设所有Git provider都有GitHub API。
- 不运行git add .。
