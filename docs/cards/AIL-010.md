## 目标与交付

将团队规则与文档接入两种工具原生加载入口；受管片段和用户正文分离；记录条件加载能力差异。

## 验收标准

- [ ] 现有用户正文保留
- [ ] 重复同步无重复片段
- [ ] 删除规则清理自己的内容
- [ ] 不支持的条件规则显式提示
- [ ] 真实会话确认可发现。

## 实施边界

- 本卡限定以上交付；新增范围先更新卡片及依赖。
- 参考实现用于理解机制，AILoom 的格式与行为以 AIL-001 契约为准。
- 宿主工具路径、格式和 Hook 能力须在实施时按官方文档与真实版本核实。
- 完成后记录验证命令、结果、支持版本及未覆盖项，再改为 Done。

## 输入与输出

输入：RuleSpec/DocSpec和工具能力；输出：原生规则文件或受管文档片段。

## 实施步骤

1. 核查每个宿主读取规则的入口。
2. 区分always/path-scoped/on-demand。
3. 不支持语义生成警告或失败。
4. 在既有文档中使用有版本和resource id的边界片段。
5. 引用文档用可移植相对路径。
6. 删除只移除自己的片段。

## 必测场景

- [ ] 用户AGENTS/CLAUDE正文保留。
- [ ] 标记缺失或重复时拒绝猜测修改。
- [ ] 含代码块和Unicode规则完整。
- [ ] 条件规则不默默变成全局规则。
- [ ] 两次apply无重复文本。

## 明确不做

- 不把所有Docs全文塞到每个会话。
- 不把Markdown文件存在等同宿主识别。
- 不修改用户无关规范。
