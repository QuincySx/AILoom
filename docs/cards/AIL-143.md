## 背景

`src/console/mod.rs` 约 2600 行，承担 service、native-files、knowledge、project 等不相关路由；取 root + `ensure_within_roots` + 403 的模式重复多次。

## 顺序步骤

1. 按领域拆成子模块（project、library、knowledge、native、service、fs），路由表保持单一入口。
2. 抽出「读取并校验目录参数」的公共函数。
3. 端口常量 47831 等字面量收为常量。

## 必须验收

- [x] 拆分前后 API 测试全部通过，行为无变化。

## 交付记录

负责人：Claude Code（2026-10-01）。

- **按领域拆分**：`src/console/mod.rs` 由约 2700 行降到 741 行，`route` 由 954 行降到 238 行，只做分派。处理器分到以下模块：
  - `http.rs`：请求与响应、解析、Host / Origin 校验；
  - `library.rs`：能力库、资源读写、MCP 掩码；
  - `profile.rs`：状态、元数据、个人配置、草稿；
  - `fs.rs`：目录授权、列目录、仓库发现、扫描、读文件、宿主探测；
  - `project.rs`：项目默认预览、有效配置、部署状态、目录发现、重新关联；
  - `sources.rs`：合集、CC Switch 迁移；
  - `knowledge.rs`：知识库、原生文件；
  - `workflows.rs`：流程工作台。

  超过 9 行的内联分支都抽成了 `<方法>_<路径>` 命名的处理函数；带守卫条件的分支（jobs 动态路径、/ui 资源）保留在路由内。`Request`/`Response` 仍从 `console` 公开导出。
- **去重**：新增 `Request::query_param`，替换 21 处手写的查询参数查找；新增 `fs::required_root`，统一「读 root → 校验授权根 → 400/403」。
- **端口常量**：`console::DEFAULT_PORT`（见 AIL-135）。
- **顺带**：`shell.html` 加空 favicon，消除每次加载都出现的 404；页面标题与 `document.title` 统一为「AILoom 本地控制台」。
- **测试工具加固**：
  - `waitFor` 在求值异常时重试；
  - CDP 命令加 30 秒超时，卡住时明确报错；
  - 冷启动的 Chrome 首次导航未完成时重新导航一次。

  冷启动问题已在 4 次全新 Chrome + 全新服务下复现排查：应用本身每次都正常渲染，问题出在测试工具新建标签页时直接带 URL 的打开方式。
