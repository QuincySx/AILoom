## 背景

返工轮次复盘中确认的两个接入摩擦点：①"管理员"需要手写 `ailoom.toml`，无脚手架引导；
② 发布链路只有设计稿，无 CI 矩阵构建。本卡补齐两者的**本地准备**部分。

## 交付

1. `ailoom source` 脚手架命令：生成 `ailoom.toml` + `resources/` 九类目录骨架，
   可选示例资源（`--minimal` 关闭）、`--git` 初始化仓库、`--force` 合并生成
   （已存在文件跳过不覆盖）；生成后用真实清单加载器 + 资源枚举自校验。
2. `.github/workflows/release.yml`：三平台五三元组矩阵构建
   （darwin arm64/x64、linux x64/arm64、windows x64），产物命名与
   `packaging/npm/cli.js`、`scripts/install.sh` 对齐（`ailoom-<triple>` + `.sha256`）；
   手动触发默认只构建上传 artifacts；GitHub Release 仅在显式 `publish=true` 时创建。
