## 按顺序执行

1. 资源库列表提供名称/类型/来源/库版本/更新状态及筛选；资源详情保持稳定资源 ID 路由。
2. 显式“导入 skill”流程组合 SourceInput→候选选择→ImportPreview→结果；失败保留输入，成功返回真实详情。
3. 来源页展示订阅、固定版本、缓存/离线与启停操作，删除展示影响预览，不与单个 skill 删除混用。
4. 详情更新动作组合检查→diff/冲突→更新库→引用目标列表→PlanPreview→JobPanel。
5. 只读源的编辑按钮明确创建个人副本；普通个人资源编辑接统一 Editor/版本冲突，不暴露真实秘密。
6. 空库提供导入动作，坏条目单项报错可修复，其余资源仍可管理。

## 交接与约束

- 组件输入为 props，输出为 onXxx 事件；基础组件不调用后端，业务组件由 services 注入；页面只负责组装、路由和状态绑定。
- 先核对依赖接口，不用生产 mock、空回调或硬编码成功补齐缺失 API。组件样例可用明确的 fixture，真实页面必须接真实 API。
- 你不是独自工作，不回滚他人修改；本卡拥有上列模块，共享入口按依赖顺序修改并记录交接。
- Token/基础组件先完成；不得在每个页面各写一套按钮、弹层、fetch、冲突处理或任务轮询。保留现有单二进制离线使用，不擅自引入 CDN/重型运行时。
- 完成真实操作验收再勾选；同步卡头、cards.json、BACKLOG 与本轮索引，相关父卡仍需原始验收。
