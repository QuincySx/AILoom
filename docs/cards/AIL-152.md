# AIL-152 · 全局 Skill：部署到用户级目录，所有项目可见

- 状态：In progress
- 优先级：P1
- 里程碑：IT-1 门禁与关卡
- 依赖：—
- 来源：2026-10-02 用户需求——少数 Skill 想全局使用，其余按项目启用；做一个全局页面，替代 CC Switch 的 Skill 托管
- 执行说明：先读 [2026-10 迭代入口](../initiatives/iteration-2026-10.md)；契约见 CONTRACTS §11.3

## 用户已定的设计

1. 页面：并入「全局配置」页（原「全局规则与 Agent」），分 Skill / 规则与 Agent 两栏。
2. 同名冲突：目录里已有的同名条目（如 CC Switch 安装的）保留并提示；用户确认后「接管」——原条目移入归档，可还原。
3. 重复：已全局启用的 Skill，项目里跳过并标注「已全局启用」。
4. 宿主：覆盖所有已支持的 agent；遵循 `.agents` 规范的共用 `~/.agents/skills`。

## 实现

- 目标目录：Claude Code `$CLAUDE_CONFIG_DIR/skills`（未设时 `~/.claude/skills`）；`.agents` 规范 `~/.agents/skills`。目录不在用户目录下时不部署。不写任何宿主全局配置文件（如 `~/.codex/config.toml`）。
- 选择存于 profile.toml `[global]`（`skills`、`targets`），与项目选择同一把锁与 revision；部署状态在 `<data_root>/global/`（托管清单、journal、锁、归档），复用项目同步的计划 / 冲突 / 恢复管道。
- 资源库与合集的渲染从 `prepare_personal` 抽出为共用的 `render_selected`，全局与项目对坏条目、缺失来源、外部目录的处理一致。
- 项目跳过以「全局托管清单里已实际部署」为准：只勾选未同步时项目照常部署；Codex 同时从 `skills.config` 去掉对应条目。附加宿主是否读取 `~/.agents/skills` 未核实，项目内照常部署。
- 全局启用计入引用：删除资源 / 移除合集前需先停用。
- CLI `ailoom global --action status|select|plan|sync|recover|takeover|restore`；接口 `/api/global/{skills,plan,select,apply,takeover,restore}`。

## 交付记录

- 首轮浏览器验收发现：`CLAUDE_CONFIG_DIR` 尚未创建且路径未规范化时被误判为「不在用户目录下」，Claude 目录未部署。已改为规范化最深的已存在祖先后再比较，并补回归测试。
- 浏览器截图发现：托管清单 key 带部署方式后缀（`…#symlink`），按完整 key 比较导致 AILoom 自己部署的条目出现在「非 AILoom 管理」列表里，且能被「接管」。改为按路径部分比较，测试补断言（托管条目不列出、接管被拒）。修复后浏览器验收 8/8 PASS。
- 未完成：真机发现与调用验证需要写入用户真实的全局目录，等用户确认后执行。
