# AIL-135 · CLI 动作与参数枚举化

- 状态：In progress
- 优先级：P1
- 里程碑：IT-2 CLI 一致性
- 依赖：AIL-134
- 对应证据：C-13、C-14、C-15、C-16、C-19（[2026-10-01 审查报告](../reviews/2026-10-01-project-review.md)）
- 执行说明：先读 [2026-10 迭代入口](../initiatives/iteration-2026-10.md)

## 背景

多个子命令的 about 与实际动作不一致，参数取值不校验，help 夹带 AIL/RW 内部编号。

## 顺序步骤

1. 动作改用 `clap::ValueEnum`，about、help 与未知动作报错从同一枚举生成；评估把 `--action` 改为真正的子命令。
2. 数值参数加范围（`code --hops 0..=2` 等），枚举参数加 ValueEnum（`recall --kind`）。
3. contribute 在知识库模式下校验 `--project`，对已无效的参数给出警告或删除。
4. web / service 复用已有服务且端口不同时提示；help 与输出移除内部卡号。
5. 为 report / packages / code / knowledge / collection / members 设计人类可读输出（从 AIL-134 移入），替代直接打印的 JSON。

## 必须验收

- [x] help 全量快照测试，动作列表与实现一致。
- [x] 非法取值在解析阶段被拒绝并返回 E0001。

## 交付记录

负责人：Claude Code（2026-10-01）。状态：In progress。第 5 步已完成 `personal`（effective / select / sync）与 `collection`（list / check / apply）的人类可读输出（`output::emit_personal` / `emit_collection`，`tests/cli_output_contract.rs` 断言不再直接打印 JSON）；剩 report / packages / code / knowledge（维护类动作）/ members 仍打印格式化 JSON。

- **动作清单统一**：12 个命令的 `--action` 加上 clap `value_parser` 可选值，这份列表就是 help、参数校验和报错的唯一来源。非法动作在解析阶段返回 E0001，并列出可选值。各命令说明里的动作清单也已与实现对齐，补上了 hooks 的 exec、report 的 retry、library 的 import-entry 和 delete、personal 的 4 个动作、collection 的 check 和 remove，并重写了 knowledge 的说明。没有改成真正的子命令，以免破坏现有调用方式。
- **参数范围**：
  - `recall --kind`（learning / rule / doc / skill）
  - `recall --limit`（1-100）
  - `code --hops`（0-2）
  - `data --max-size-mb`（大于 0）
  - `import --kind`（learning / doc）
  - `contribute --provider`（auto / manual）
- **contribute**：项目知识库模式下，`--project` 等只用于团队源 PR 流程的参数如果被显式传入，会提示「不生效」并写进 `warnings`；help 中也标注了「仅团队源 PR 流程」。
- **端口**：新增 `console::DEFAULT_PORT` 常量，代码里不再出现端口字面量。`web` 与 `service start` 的 `--port` 改为可选；复用已运行的服务且端口不同时，给出警告并返回 `requested_port`，已在隔离数据目录中实测。
- **内部卡号**：help 中的 AIL / F 编号全部去除。

验证：
- `tests/cli_actions.rs`：从 help 读出每个可选动作逐个执行，断言都被实现识别，覆盖 50 多个动作。
- 非法取值的实测：`recall --kind bogus`、`recall --limit 0`、`code --hops 5`、`data --max-size-mb 0`、`library --action bogus` 均返回 E0001。
