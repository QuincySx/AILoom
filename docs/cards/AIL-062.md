- 修复的缺陷：
  1. 资源库任一条目（即使未启用）定义无效，所有项目的 personal plan / sync 全部失败；新导入也失败（发布后整库严格校验）；坏条目也删不掉（删除先严格枚举整库）
  2. 已部署资源的定义坏掉后，下一次 sync 会把它的已部署文件当多余项清理掉
  3. 网页打开坏条目返回 422「修复后即可继续编辑」，但网页编辑正是修复入口；按 `id.ends_with(stem)` 匹配会把 `…/xb` 错配到坏条目 `b`

  5. `library delete --skill` 只认完整资源 ID，写 skill 名时只回「资源不存在」；现与 check-update / update 一致可写 skill 名
  6. 带 BOM 的 SKILL.md 未识别 frontmatter，导入后原 frontmatter 被包进正文、description 丢失；CRLF 文件导入后换行混用；结束标记前多插空行
  7. 导入校验错误大多没有修复提示；projects 限定错误提示「联系团队管理员更新 ailoom.toml」对个人资源库是误导
