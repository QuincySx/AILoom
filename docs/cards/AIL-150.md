## 背景

为「没测过」的验收项补测试时，实测出以下问题：

1. 个人层只要选用了一个定义无效的 MCP（如缺 `command`），整个 plan / sync 都失败，其他资源也部署不了。
2. 个人 CLI sync 的错误码被包成 E9000。
3. 「不支持」的资源被记进 `skipped_conflicts`，网页于是把正常应用报成「部分改动未完成，冲突文件已保留」。
4. 部分失败时：
   - CLI 仍以 0 退出；
   - 未部署条目的说明写着「已落盘」；
   - 网页任务结果缺失败原因与恢复点，进度写着「应用完成」；
   - 网页没有任何撤回入口，下一次应用必然被恢复点挡住。
5. 给出的恢复命令 `ailoom sync --recover` 对非 Git 文件夹项目不可用。

## 修复

1. 新增 `adapters::render_lenient`（个人层使用）：先按严格模式整体渲染，出错时找出有问题的资源，列为 unsupported 并附原因，其余照常渲染。团队源仍严格。
2. `cli_sync` 保留原始错误码。
3. `ApplyReport` 新增 `skipped_unsupported`，`skipped_conflicts` 只放真正的冲突。网页成功页列出「暂不支持、未部署」的项。
4. 部分失败时：
   - CLI 返回 E4004 并以退出码 13 结束，错误 JSON 的 `context` 中带完整结果；
   - 验证条目如实写「未写入」；
   - 网页任务结果带 `failed` 与 `pending_journal`，进度写明失败。
5. 新增 `ailoom personal --action recover` 与 `POST /api/project/recover`：与个人同步用同一方式定位工作区，Git 与非 Git 都适用，并持同步锁。网页在失败或存在恢复点时提供「撤回已写入的部分」按钮。
