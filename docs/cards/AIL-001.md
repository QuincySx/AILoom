## 目标与交付

定义 Team、逻辑 Project、Role、WorkspaceBinding、ResourceId、Revision；配置版本与示例；记录共享范围和命名冲突规则。

## 验收标准

- [ ] 角色与项目取并集而非覆盖
- [ ] 一个工作区允许零到多个项目
- [ ] 逻辑项目、仓库身份、当前 checkout 三者有独立字段
- [ ] MCP/Agent 的项目选择规则明确标为 AILoom 设计。

## 实施边界

- 本卡限定以上交付；新增范围先更新卡片及依赖。

- 宿主工具路径、格式和 Hook 能力须在实施时按官方文档与真实版本核实。

## 实施步骤

1. 逐项核对术语。
2. 固定资源身份为来源/类型/命名空间/名称。
3. 把角色与项目选择和物理安装作用域分成两张表。
4. 定义 MCP/Agent 项目筛选扩展。
5. 给 A/B/shared 场景写期望资源集合。
6. 冻结文件格式、版本与向后兼容规则。

## 必测场景

- [ ] 开发者角色+A项目得到 common/dev/A。
- [ ] 同一目录绑定 A+B 不创建组合角色。
- [ ] 不同 namespace 同名输出显式冲突。
- [ ] 零项目不能意外激活 A。
- [ ] 未知版本和非法路径示例必失败。
