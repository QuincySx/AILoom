## 目标与交付

执行经校验的计划；原子文件替换、持有者锁、备份/恢复和失败日志；提交状态与实际写入一致。

## 验收标准

- [ ] 并发 sync 不互相覆盖
- [ ] 中途失败可重试或恢复
- [ ] 释放锁验证 owner
- [ ] 旧计划遇到本地变动拒绝执行
- [ ] 重复同步无额外变化。

src/sync/apply.rs、src/sync/lock.rs、src/sync/journal.rs、tests/sync_apply.rs。已有等价模块时复用，不为匹配路径复制逻辑；共享类型只有一个定义。

## 输入与输出

输入：SyncPlan；输出：ApplyReport、部署清单和恢复journal。

## 实施步骤

1. 获取workspace级原子锁并记录owner。
2. 逐项重查目标前置hash。
3. 先暂存并flush，再同文件系统rename。
4. 记录每项旧值与已完成操作。
5. 全部成功才推进revision。
6. 失败保存恢复点。
7. 恢复只还原仍匹配本次写入的内容，保留后来的人为修改。

## 必测场景

- [ ] 两个进程同时apply只有一个获得锁。
- [ ] 计划后用户修改导致拒绝。
- [ ] 第N项注入写失败可恢复。
- [ ] 进程崩溃下次可发现journal。
- [ ] 恢复期间用户编辑不能被覆盖。
- [ ] 旧进程释放锁不能删新owner锁。

## 明确不做

- 不承诺多文件rename天然事务。
- 不以sleep代替锁。
- 不自动清理无法确认归属的临时文件。
