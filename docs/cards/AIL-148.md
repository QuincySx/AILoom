# AIL-148 · 并发 sync 误把进行中的 journal 当作崩溃遗留

- 执行说明：先读 [2026-10 迭代入口](../initiatives/iteration-2026-10.md)

## 背景

两个 sync 进程同时运行时，后到的进程会先检查 journal 目录，再去拿同步锁。于是它看到的是先到进程正在写的 journal，报出 E4005「存在未完成的同步 journal，先恢复再同步」，并建议运行 `sync --recover`。而 `--recover` 本身不加锁：用户照提示操作，就会在另一个 sync 进行到一半时回滚它的写入。

## 顺序步骤

1. `sync::apply` 改为先拿锁再检查遗留 journal：持锁时仍存在的 journal 才是真正的崩溃遗留。发现遗留时先释放锁再返回。
2. `sync --recover` 也拿同一把锁，恢复与同步互斥。

## 必须验收

- [x] 单元测试 `concurrent_sync_reports_lock_not_pending_journal`：另一方持锁并已写出进行中的 journal 时，本次返回 E4003（锁被持有），不再是 E4005。
- [x] 全量测试连续三轮 502 通过 / 0 失败，`tests/e2e.rs` 并发用例不再间歇失败。
