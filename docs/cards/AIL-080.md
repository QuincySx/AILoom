## 按顺序执行

1. 盘点旧页面函数、全局变量、API 路由和现有自动化定位器，产出迁移映射；旧交互先建立可复现基线。
2. 采用原生 ES modules + CSS 模块文件（无新增运行时框架），沿用 Rust 单二进制嵌入分发；web.rs 只保留 HTML/bootstrap，不再承载业务页面字符串。
3. 划分 tokens、components、services、state、features、pages、app；提供逐模块迁移顺序，旧入口只作过渡，不能长期保留两套状态。
4. 列出页面清单与每个用户动作的 request/response/error/目标/版本字段；现有与待补 API 明确区分，不靠前端捏造后端成功。
5. 实现最小静态资源嵌入与 module 加载链路，正确 MIME、未知资源 404、无任意文件读取；离线启动无 CDN 依赖。
6. 定义 mount(container, props) → { update(nextProps), destroy() } 生命周期与 onXxx 回调约定，页面销毁必须解绑监听/计时器。

## 交接与约束

- 组件输入为 props，输出为 onXxx 事件；基础组件不调用后端，业务组件由 services 注入；页面只负责组装、路由和状态绑定。
- 先核对依赖接口，不用生产 mock、空回调或硬编码成功补齐缺失 API。组件样例可用明确的 fixture，真实页面必须接真实 API。
- 你不是独自工作，不回滚他人修改；本卡拥有上列模块，共享入口按依赖顺序修改并记录交接。
- Token/基础组件先完成；不得在每个页面各写一套按钮、弹层、fetch、冲突处理或任务轮询。保留现有单二进制离线使用，不擅自引入 CDN/重型运行时。
- 完成真实操作验收再勾选；同步卡头、cards.json、BACKLOG 与本轮索引，相关父卡仍需原始验收。
