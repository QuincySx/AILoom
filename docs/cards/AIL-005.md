# AIL-005 · 项目绑定与 init/status 命令

- 状态：Done
- 里程碑：M1
- 相对规模：M（复杂度提示，不是工时承诺）
- 依赖：AIL-001, AIL-003, AIL-004

## 目标与交付

init 绑定团队源、工作区、项目数组和角色；status 展示有效来源及待同步状态；可提交声明与本机数据分离。

## 验收标准

- [ ] 重复 init 幂等
- [ ] 非法项目/角色明确报错
- [ ] 新 worktree 可独立绑定
- [ ] 仅一个逻辑项目时也不默认授权式激活
- [ ] 状态不含机器秘密。

## 实施边界

- 本卡限定以上交付；新增范围先更新卡片及依赖。
- 参考实现用于理解机制，AILoom 的格式与行为以 AIL-001 契约为准。
- 宿主工具路径、格式和 Hook 能力须在实施时按官方文档与真实版本核实。
- 完成后记录验证命令、结果、支持版本及未覆盖项，再改为 Done。

## 文件职责（建议布局）

src/commands/init.rs、src/commands/status.rs、src/config.rs、tests/init.rs。已有等价模块时复用，不为匹配路径复制逻辑；共享类型只有一个定义。

## 输入与输出

输入：团队源、--project可重复、--role、cwd；输出：可提交声明+不含秘密的本机binding+初始source lock。

## 实施步骤

1. 加载并校验团队manifest。
2. 解析当前workspace。
3. 展示有效选择。
4. 原子保存声明和binding。
5. 重复绑定只改显式参数。
6. status显示声明/锁/实际部署是否一致。
7. 定义跨机器clone后的恢复步骤。

## 必测场景

- [ ] A目录init A、B目录init B，缓存可共享但binding不同。
- [ ] 重复init无冗余变更。
- [ ] manifest只有A但用户不选时仍为空。
- [ ] 未知项目返回可读错误。
- [ ] 仓库移动后重新绑定不覆盖旧工作区。

## 明确不做

- 不要把成员参与历史当成当前目录激活集合。
- 不要在init里顺手上传会话或修改其它工作区。
