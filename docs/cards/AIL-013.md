## 目标与交付

检查 Git、绑定、源、目标目录、资源冲突和适配能力；卸载按托管清单运行，提供预览。

## 验收标准

- [ ] 诊断给出可执行修复建议
- [ ] 卸载保留用户修改及非托管内容
- [ ] 其它 worktree 不受影响
- [ ] 卸载后重复运行幂等。

## 实施边界

- 本卡限定以上交付；新增范围先更新卡片及依赖。

- 宿主工具路径、格式和 Hook 能力须在实施时按官方文档与真实版本核实。

## 输入与输出

输入：workspace或显式user scope；输出：诊断列表/卸载计划及执行结果。

## 实施步骤

1. 复用source/binding/capability校验。
2. 每条问题给错误码、位置、原因和修复命令。
3. 卸载转成统一删除计划。
4. 用户改动保持冲突。
5. 仅无引用缓存可在另一个明确GC入口处理。

## 必测场景

- [ ] 卸载A不影响B/用户级配置。
- [ ] 计划保留手改Skill。
- [ ] 已不存在文件幂等。
- [ ] 损坏managed清单不得猜删。
- [ ] doctor离线仍能检查本地。
- [ ] 无论诊断失败不修改状态。

## 明确不做

- 不把doctor变自动修复器。
- 不递归删除整个工具目录。
- 不在卸载时删除团队Git远端或用户缓存总目录。
