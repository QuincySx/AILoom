## 按顺序执行

1. 流程列表创建/进入具体 WorkflowId，详情组装阶段列表、实际 skill 绑定和关联文档列表。
2. 在同一工作上下文切换对齐/spec/ticket/实现/验收文档，稳定 ID 路由保持草稿与版本。
3. 提供导入已有文档、重命名、编辑、冲突比较、输入版本查看与明确标记复核。
4. 导出单项/包展示授权目标和 diff，用户确认才执行；返回流程详情能看到成功/冲突而非只弹 toast。
5. 缺阶段 skill、无文档、下游需复核、并发冲突、失效目标都有可执行入口。
6. 不把“关联了 implement skill”标为实现已完成，不加入自动模型调用或自动发布。

## 交接与约束

- 组件输入为 props，输出为 onXxx 事件；基础组件不调用后端，业务组件由 services 注入；页面只负责组装、路由和状态绑定。
- 先核对依赖接口，不用生产 mock、空回调或硬编码成功补齐缺失 API。组件样例可用明确的 fixture，真实页面必须接真实 API。
- 你不是独自工作，不回滚他人修改；本卡拥有上列模块，共享入口按依赖顺序修改并记录交接。
- Token/基础组件先完成；不得在每个页面各写一套按钮、弹层、fetch、冲突处理或任务轮询。保留现有单二进制离线使用，不擅自引入 CDN/重型运行时。
- 完成真实操作验收再勾选；同步卡头、cards.json、BACKLOG 与本轮索引，相关父卡仍需原始验收。
